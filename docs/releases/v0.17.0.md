# suta 0.17.0

suta 0.17.0 adds screen conventions for flows suta did not cover, chooses type size and fonts by industry, and draws a clearer line between presenting what was asked for and adding what was not. It also fixes and extends the benchmark measurement. No patterns were added.

- **Screen conventions (24 types).**
  - New: filters and sorting, writing screens, and article and review pages.
    - Filters and sorting: one chip per condition, each opening a sheet for that condition. The chip shows the chosen value and the result count updates.
    - Writing screens are split in two. Plain composers use a borderless title and body. Multi-field forms use one input style, bold labels with required marks, controls chosen by the kind of value (segmented control, chips, stepper with a default, sheet), and an input column plus an optional side panel on desktop.
    - Article and review pages get a site header, a title block, a wide lead image and a 640–720px body column.
  - Rewritten: dashboards and reports. Metrics are grouped as tabs in one panel above a large line chart instead of a row of separate cards. The period control has presets, a custom range and a comparison.
  - Sideways-scrolling rows now start at the page margin.
- **Usability rules.** These are now usability problems that suta fixes even in existing styles:
  - values cut off by their box at any width
  - table columns dropped or left outside the first narrow screen
  - field names or required marks that exist only inside placeholders

  Sample numbers on a screen must agree with each other. Sub-screens keep a back or close button.
- **Type by industry.** The guidance comes from 48 websites in 9 industries.
  - Body size depends on reading conditions: public services and long-form 17–19px, general screens 15–16px, dense tool and shopping lists 14px, fashion menus 12–13px.
  - Display type is heavier or lighter depending on the industry. Serif is for editorial headings and quotes, monospace only for code.
  - New tokens `--font-serif` and `--font-mono`. The serif stack falls back to sans when no Korean serif is installed, so digits and Latin letters do not render in a different face from Hangul.
- **Request scope.** suta still does not add features, sections or data that nobody asked for. Those are suggested in the report.
  - Within scope: presenting requested content (a rating bar, required marks, numbered subheads, chips and steppers) and screen chrome (back and close, a site header).
  - When the project has no menu, site menu names are placeholder content (3–5 common section names), reported as values to replace.
- **Accent color.** Industry clichés such as "analytics tools are blue" no longer count as a reason for a color.
- **Benchmark measurement.**
  - Closed bottom sheets no longer appear at the end of full-page screenshots.
  - Text that is cut off or spills out of its box, and table columns outside the first 390px screen, are now counted.
  - Generation cost is recorded in the result files.

Measured with Claude Code on five sets of requests for these screen types, 3 runs per condition. The table shows blind judgments, suta : without; each cell lists the requests in order as "default model·other model":

| Requests | Judgments |
|---|---|
| Composer · product filters · SaaS report | 2:4·3:3 / 2:4·1:5 / 2:4·2:4 |
| Book review · stay filters · store sales report | 1:5·1:5 / 5:1·5:1 / 2:4·1:5 |
| Secondhand listing · complaint status · magazine article | 0:6·1:5 / 2:4·3:3 / 1:5·0:6 |
| Meetup creation · library statistics · album review | 1:5·1:5 / 6:0·6:0 / 2:4·2:4 |
| Clinic booking · course creation · travel article | 4:2·4:2 / 3:3·3:3 / 0:6·0:6 |

- Accessibility violations (axe) were 0 on the suta side in every set. Some measurements went against suta: all three course-creation runs animated a width (the canonical `segmented-control` thumb), meetup creation had 0.67 touch targets under 24px per page (0 without suta), and the SaaS report had 1.33 nested boxes per page (1 without suta). One library-statistics run scrolled sideways at 320px, as did one run without suta.
- Across the 15 requests, suta lost the blind comparison 33 : 57 with both judge models.
  - It won 3 requests with both models: stay filters, library statistics and clinic booking.
  - It lost 9 with both models: 3 of the 4 report screens, 4 of the 5 writing screens and all 3 article pages.
- Per request, the median generation time was 0.95–2.2 times and the median cost 1.2–3.3 times that of the runs without suta.
- The last fixes (desktop forms, article presentation, the request-scope boundary) were made after the last set and were not measured again.
- One judge model is also the generating model.

Validation: build, lint, 853 tests and 476 selection checks passed. The skill audit reported no errors or warnings.

## Install

Claude Code, in the chat:

```text
/plugin marketplace add Guksu/suta
/plugin install suta@suta
```

Codex, in a terminal:

```bash
codex plugin marketplace add Guksu/suta
codex plugin add suta@suta
```

Approve suta's post-edit check in Codex `/hooks`.

Skill only, without the post-edit hook:

```bash
npx skills add Guksu/suta --skill suta
```

## Update

For Claude Code, run `claude plugin marketplace update suta` followed by `claude plugin update suta@suta`, then start a new session.

For Codex, run `codex plugin marketplace upgrade suta`, then check and update the installed suta version in the app's plugin settings. Marketplace refresh alone does not confirm an installed-plugin update.

For a skills CLI install, run `npx skills update suta` from the project where you installed it; select the scope where suta is installed. If you used our install script, rerun it with the same destination.

These commands follow the current marketplace branch. The source archive on this release preserves version 0.17.0.
