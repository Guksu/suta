# suta 0.16.0

suta 0.16.0 is about using suta in projects that already have a design, and about what the agent reads first. It adds no patterns and changes no check rules or severities.

- **Priority order:** what the user explicitly asked for → the project's existing design system → real usability problems → suta's defaults. In a project with its own tokens, components or brand colors, suta no longer swaps colors, cards or screen structure for its defaults. It fixes usability problems only (keyboard access, focus, contrast, overflow, reduced motion), changes just the value at fault, and reports what it changed.
- **Request scope:** sections and items nobody asked for (support, terms and version rows in settings; testimonials and logo bands on landing pages; a search bar on a home screen) are suggested in the report instead of added. Requested states such as an error state must be reachable on screen.
- **Factual content:** for a real service, customer logos, user counts, testimonials and performance numbers come only from material the user provides. Without it, the section is left out and the agent asks for the material. Invented values are used only in work the user calls a mockup or demo, and the screen itself labels them as examples instead of a note in a README or comment.
- **Entry document:** `SKILL.md` now holds what every UI request needs: the priority order, usability rules, factual-content rules, a table of which document to read for which request, final checks and a pattern index. It went from 57,732 to 24,743 bytes. Defaults for projects without a design standard, per-screen-type checks and the pattern catalog moved to `skills/suta/references/` (`defaults.md`, `checklist.md`, `catalog.md`). The repository check now fails if a core section is missing, a reference document is not linked from `SKILL.md`, or a path in it does not resolve in the installed skill.
- **Post-edit check messages:** warnings that are usability problems (`input-zoom`, `accent-contrast`, `viewport-height` and others) are marked `[사용 문제]` and listed first. Style warnings say to leave values that come from the project's own design system.
- **README and demo:** the README describes three things (layout and interaction rules, pattern code, the post-edit check) and shows the 0.14 measurements with the unfavorable rows. The demo home page now opens with one example (a walking-rewards app, suta 0.11.0): focus on the celebration dialog, idle infinite animations and axe violations, with the added time and cost, followed by demos to try with a keyboard and install steps. The demo's README link now opens the README in the page's language.

Nothing in this release was re-measured with generated screens. The shorter entry document has not been shown to reduce tokens, time or cost per request, because the agent also reads the reference documents it needs. The effect of leaving out unrequested sections on blind preference is also unmeasured; one reason a judge preferred the 0.14 landing page was its customer logos and numbers.

Validation: build, lint, 837 tests and 476 selection checks passed. The pattern audit and the demo audit reported no errors or warnings. Keyboard focus, overflow at 320, 390 and 1280px, and the demo links were checked in Chromium.

## Install

Claude Code, in the chat:

```text
/plugin marketplace add Guksu/suta
/plugin install suta@suta
```

Codex, in a terminal:

```bash
codex plugin marketplace add Guksu/suta
codex plugin add suta@suta
```

Approve suta's post-edit check in Codex `/hooks`.

Skill only, without the post-edit hook:

```bash
npx skills add Guksu/suta --skill suta
```

## Update

For Claude Code, run `claude plugin marketplace update suta` followed by `claude plugin update suta@suta`, then start a new session.

For Codex, run `codex plugin marketplace upgrade suta`, then check and update the installed suta version in the app's plugin settings. Marketplace refresh alone does not confirm an installed-plugin update.

For a skills CLI install, run `npx skills update suta` from the project where you installed it; select the scope where suta is installed. If you used our install script, rerun it with the same destination.

These commands follow the current marketplace branch. The source archive on this release preserves version 0.16.0.
