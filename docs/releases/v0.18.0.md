# suta 0.18.0

suta 0.18.0 adds depth rather than breadth. Earlier versions grew by adding one screen convention each time a request lost a comparison. This version adds the reasoning behind those conventions, a standard for finishing each requested element, a layer system for shadows and stacking order, and "states and edge cases" for 22 patterns. It also fixes defects found along the way.

- **Screen design order (`references/design.md`, new).**
  - Write the screen in one sentence: who comes, to do what, and what they do before leaving.
  - Pick one of six jobs (choosing, inspecting, entering, monitoring, conversing, moving on). Each job has a skeleton, and the 24 screen conventions are variations of these six.
  - Sort requested elements into decision, evidence and reference.
  - When no screen type fits, borrow the skeleton from a convention with the same job.
- **Detail standard (`references/detail.md`, new).**
  - Five questions for every requested element: realistic content, a control that fits the kind of value, a full set of states, context next to values, and a response after pressing.
  - Rules for sample data, a table of controls by value type, and component states (hover, pressed, focus, selected, disabled, busy, error, empty, loading).
  - How to fix a screen that looks thin without adding sections nobody asked for.
- **Elevation (`elevation.md`, new) and tokens.**
  - Four layers: resting, stuck, floating, covering. Cards rest and get no shadow. Menus and toasts float.
  - Tokens: three shadow steps (`--shadow-low`, `--shadow-raised`, `--shadow-overlay`), `--scrim`, and five stacking steps (`--z-sticky` 30, `--z-overlay` 40, `--z-popover` 50, `--z-viewer` 90, `--z-toast` 100).
  - Pattern CSS now looks up these tokens first and falls back to the same values, so patterns look the same without the token file.
  - Measured on 47 public websites. Shadow values for menus and modals were not measured; they consolidate what the patterns already used.
- **Audit rules (26 → 28).** `glow-shadow` flags colored blurred shadows. `shadow-variety` flags four or more shadow values in one file. Both are taste warnings.
- **Patterns (22 of 57).** Each got a "states and edge cases" table and a "use together" list, written from the code. Gaps found in the code were fixed:
  - skeleton: a gate that delays showing by 200ms and keeps the skeleton for at least 400ms (`createSkeletonGate`).
  - select: type-ahead, disabled options, a framework-free core (`createSelect`).
  - bottom-sheet: focus moves in, is trapped and returns; a closed sheet is out of the tab order; optional close on the back button.
  - tooltip: hoverable, dismissible and persistent (WCAG 1.4.13); flips at screen edges.
  - Forced-colors support in 17 patterns, 44px touch targets on switches and checkboxes.
- **Defects fixed.**
  - The bottom tab bar (z-index 50) was drawn above an open sheet (41) and its scrim.
  - The floating-label label and the select placeholder were 3.2:1 on white. They are now 4.5:1 or more.
  - The current carousel dot bled into a 30px circle (since 0.15.0).
  - Quantity stepper buttons did not respond to the keyboard.
  - The tab indicator jumped instead of sliding.

Measured with Claude Code on three requests that match no screen convention (parcel tracking, waitlist sign-up, leave request), suta 0.17 against 0.18, 2 runs per condition:

| | 0.17 | 0.18 |
|---|---|---|
| Blind judgments (default model, other model) | 4, 3 | 8, 9 |
| 320px overflow, clipped text, text under 12px | 0 | 0 |
| Accessibility violations (axe, per app page) | 0 | 0.25 |

- Rendered metrics were almost the same in both versions.
- The new reference documents were rarely opened in the 0.18 runs: `design.md` 0 of 6, `detail.md` 1 of 6, `elevation.md` 0 of 6. The judgment difference most likely comes from the sentence added to the always-read procedure. After the measurement, the procedure was changed to say "read" these documents explicitly. That change was not measured.
- Two runs per condition is a small sample, and one judge model is the model that built the screens.

## Behavior changes

If you copy these patterns again, note the following.

- `tooltip`: the open bubble receives the pointer, does not open on touch and closes on press. Long text wraps at 20rem instead of staying on one line.
- `dropdown-menu`: opens in the browser's top layer where popover is supported, so `z-index` no longer applies to it.
- `infinite-scroll`: `retry()` loads immediately. `loading-button`: pressing during the failure state retries.
- `carousel`: the hook's `autoplayOn` now means "the user left autoplay on". `sticky-header` collapses earlier by the header height.
- `press-feedback` transitions `scale` and `translate` instead of `transform`.
- Default colors in patterns are now neutral grays and one error red (`--color-danger`). Projects that set the public variables are unaffected.

Checked in headless Chromium only. Screen readers, iOS, Android and Safari were not tested.

## Install

Claude Code, in the chat:

```text
/plugin marketplace add Guksu/suta
/plugin install suta@suta
```

Codex, in a terminal:

```bash
codex plugin marketplace add Guksu/suta
codex plugin add suta@suta
```

Approve suta's post-edit check in Codex `/hooks`.

Skill only, without the post-edit hook:

```bash
npx skills add Guksu/suta --skill suta
```

## Update

For Claude Code, run `claude plugin marketplace update suta` followed by `claude plugin update suta@suta`, then start a new session.

For Codex, run `codex plugin marketplace upgrade suta`, then check and update the installed suta version in the app's plugin settings. Marketplace refresh alone does not confirm an installed-plugin update.

For a skills CLI install, run `npx skills update suta` from the project where you installed it; select the scope where suta is installed. If you used our install script, rerun it with the same destination.

These commands follow the current marketplace branch. The source archive on this release preserves version 0.18.0.
