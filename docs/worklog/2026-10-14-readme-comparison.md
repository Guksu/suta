## 1. 개요

0.14.0을 main에 합친 뒤 사용자가 README의 AS-IS / TO-BE를 최신 버전으로, 차이가 잘 보이는 이미지로 바꿔 달라고 했다. 이전 이미지는 suta 0.8의 쇼핑 앱 화면이었다. 두 조건 모두 주황 계열에 음식 사진이 많아 차이가 덜 보였다. 같은 요청을 suta 없이와 suta 0.14.0으로 새로 돌려 이미지를 다시 만들었다.

## 2. 작업내용

- **실행**: 퍼블리싱 벤치마크의 요청 8개 중 넷(일정 관리 SaaS 랜딩, 판매자 대시보드, 로그인, 설정)을 실행 전에 골랐다. AI 티가 잘 드러나는 데스크톱 SaaS 화면 둘과 모바일 화면 둘이다. 조건마다 2번, 모두 16번 돌렸다(`scripts/benchmark/run.mjs`, 측정은 `measure.mjs`).
- **이미지** `docs/assets/benchmark-as-is-to-be.jpg`(1712×2413)
  - 왼쪽 열은 AS-IS, 오른쪽 열은 TO-BE이고, 각 조건의 첫 실행이다.
  - 위부터 랜딩(1440px 전체 캡처의 위 1,600px), 대시보드(1280px 첫 화면), 로그인·설정(390px 첫 화면 844px)이다.
  - 랜딩은 처음에 1280 첫 화면만 넣었다. 그러면 두 히어로가 비슷해 보였다. 첫 화면 두 장 높이로 늘리자, 한쪽은 아이콘 카드 세 장이고 다른 쪽은 제품 화면·증거 띠라는 구조 차이가 보였다. 실행은 바꾸지 않았고, 자르는 높이만 바꿨다.
- **README 2벌**: 이미지와 설명 문장을 바꿨다. 새 이미지에는 음식 사진이 없어 설명 줄의 사진 출처 링크를 뺐다.
- **비교 문서 2벌**: 맨 앞에 "데스크톱·모바일: 랜딩·대시보드·로그인·설정 (suta 0.14)" 절을 더했다. 요청문, 이미지, 8번 전체의 측정표, 요청별 블라인드 판정을 넣었다.
- **측정**(8번씩)

  | | suta 없이 | suta 0.14 |
  |---|---|---|
  | 강조색 | 파랑·남색·보라 8 | 초록 4, 거의 검정 2, 파랑 1, 주황 1 |
  | 그라데이션·흐림·큰 그림자 | 12 | 1 |
  | 테두리·그림자 상자 | 52 | 18 |
  | 24px 미만 터치 영역 | 25 | 7 |
  | 12px 미만 글자 | 24 | 0 |
  | 접근성 위반 요소 | 16 | 1 |
  | 생성 시간·비용(중앙값) | 65초, 0.18달러 | 185초, 0.60달러 |

- **블라인드 판정**: suta 9 : 7(기본 모델), 7 : 9(다른 모델)로 우열은 없었다. 요청별로는 대시보드 4 : 0·4 : 0, 랜딩 3 : 1·3 : 1, 로그인 2 : 2·0 : 4, 설정 0 : 4·0 : 4였다.
- 릴리스 0.14.0의 노트 초안을 영어로 썼다. 0.11.0 이후 세 버전(0.12·0.13·0.14)을 묶었다. 이 세션의 도구로는 GitHub 릴리스를 만들 수 없어, 사용자가 만들도록 미리 채운 링크로 넘겼다.

## 3. 주의사항

- 화면 비교 규칙(AGENTS.md 12)에 따라 이미지는 첫 실행으로만 만들었다. 대시보드의 suta 첫 실행은 막대그래프 카드가 세로로 지나치게 길다. 이 흠도 그대로 실었다.
- 설정은 이번에도 판정 모델이 둥근 카드 묶음과 테마 세그먼트를 골랐다. 이는 `docs/research/2026-10-14-settings-landing.md` 6절과 같은 경향이다.
- 로그인에서는 판정 모델이 suta 쪽의 오류 상태를 찾지 못했다. suta가 요청한 상태를 첫 화면에 보이게 하는지는 다음 점검 거리다.
- suta 랜딩 첫 실행은 제품 화면 그림에 `role="img"`를 달지 않았다. 관례를 읽고도 빠뜨렸고, 편집 후 검사도 `nested-card`를 warn으로만 알린다.
- 이전 이미지 `docs/assets/as-is-to-be.jpg`는 비교 문서의 이커머스 절에서 계속 쓴다.
- 원자료(실행 폴더·측정·판정 JSON)는 저장소 밖(`/home/user/suta-bench/readme14`)에 있다.
