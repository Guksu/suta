# 진입 문서 정리 — 검사가 잡는 규칙의 중복 설명 덜기

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-11-27 |
| 작성 | 에이전트 |
| 관련 경로 | `skills/suta/SKILL.md`, `AGENTS.md` |

## 1. 개요

`SKILL.md` 본문이 한도 30,000바이트에서 5바이트 남았다. 진입 문서에 넣은 한 줄(강조색)은 다음 실행부터 지켜졌다. 늘 읽히는 자리를 다음 규칙에 쓸 수 있게 비운다.

## 2. 작업내용

기준은 하나다. 편집 후 검사(`scripts/audit.mjs`)가 고칠 방법과 함께 돌려주는 규칙은 진입 문서에 길게 적지 않는다. 검사가 잡지 못하는 규칙은 그대로 둔다.

| 곳 | 전 | 후 |
|---|---|---|
| "사용 문제와 취향"의 검사 구분 | error 규칙 예 7개, 취향 warn 이름 11개 나열 | error는 모두 사용 문제, 사용 문제 warn 이름만(`table-squeeze` 더함), 나머지는 취향 |
| "늘 지키는 선"의 모션 | 표 6행 | 목록 4줄(움직이는 속성·모션의 쓰임·동작 줄이기는 그대로, `transition: all`·`setInterval`·`will-change`는 "검사가 잡는다" 한 줄) |
| 넘침·크기 표 | 10행 | 6행 + 검사가 잡는 것 한 줄(`100vh`·16px 미만 입력칸·확대 막기·열 없는 화면 높이 grid·`object-fit: fill`·11px 미만 글자) |
| 접근성 표 | 확대 막기 행 | 위 한 줄로 옮김 |
| 사실 정보 | 3열 표 5행 | 목록 5줄(내용은 같다) |
| 읽을 문서 표 | "모든 UI 작업 — 이 문서 전체" 행 | 뺌 |

- 본문 29,995 → 28,428바이트(여유 5 → 1,572).
- 덜어낸 규칙의 고칠 방법은 `patterns/layout-audit/PATTERN.md`·`patterns/motion-audit/PATTERN.md`의 규칙표와 검사 출력에 그대로 있다.
- `AGENTS.md`의 진입 스킬 지침 문단에 자리 쓰는 기준을 적었다(검사가 잡지 못하고 어느 화면에나 걸리는 규칙만, 여유 1,000바이트 이상).
- 조작·피드백 표(검색 응답·무한 스크롤·토스트·키보드와 탭 바 등)는 줄이지 않았다. 검사가 잡지 못하는 결함이고, 패턴 문서는 읽히지 않는 일이 많다.
- 화면 결과를 바꾸는 변경이 아니라서 전후 이미지는 없다.

## 3. 주의사항

- 줄인 뒤 claude CLI로 다시 돌려 보지 않았다. 검사를 돌리지 못하는 환경(Node 22.18 미만, 훅 없이 스킬만 설치하고 절차 8을 건너뛴 경우)에서는 덜어낸 규칙이 지켜지지 않을 수 있다.
- 처음 쓸 때 `transition: all`이나 `100vh`를 쓰고 검사에 걸려 고치는 실행이 늘 수 있다(편집 한 번 더).
- **정정(같은 날).** 처음 판은 근거로 "모델은 진입 문서만 읽는 일이 많았다"고 적었다. 읽은 파일을 세는 도구의 결함이었다(셸 변수 경로·CSS를 세지 못함). 다시 세면 모델은 진입 문서가 가리킨 파일(화면 관례·`screen-kit`·`defaults.md`)을 골라 읽는다. 자리를 비운 판단(검사가 잡는 규칙의 중복 설명을 던다)은 이 근거와 무관해 그대로 둔다.
