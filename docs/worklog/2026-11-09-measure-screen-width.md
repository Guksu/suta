# 측정 — 넘친 페이지의 화면 크기

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-11-09 |
| 작성 | Claude Code |
| 관련 경로 | `scripts/benchmark/measure.mjs`(`clipProbes`·`renderMetrics`), `docs/benchmark(.en).md`, `docs/research/2026-11-06-reference-gaps.md` 14절, `docs/worklog/2026-11-06-gap-sixth.md` |

## 1. 개요

여섯 번째 재측정(PR #63)에서 "측정의 빈틈"을 하나 적었다. suta 없이 미용 예약 1번째 실행에서 하단 바의 금액 문구가 화면 끝에서 잘렸는데, 측정은 "칸 밖으로 잘린 글자"로 세지 않았다는 내용이다. 후속으로 이것을 고치려고 실제 페이지를 들여다봤다. 그런데 원인은 달랐다.

- 이 페이지는 390px에서 가로로 넘쳤다. 측정은 이것을 `overflow390`으로 이미 셌다.
- 모바일 에뮬레이션은 넘친 페이지를 휴대폰처럼 다룬다. `innerWidth`가 콘텐츠 폭(883px)까지 늘어나고, `left: 0; right: 0`인 고정 바도 883px이 된다.
- 금액 문구(글자 218~403px)와 예약 버튼(상자 526~666px)은 바 안에 있다. 캡처가 왼쪽 390px만 잘라 찍어서 잘린 것처럼 보였다.
- 넘친 원인은 날짜 줄의 숨긴 라디오 입력(`position: absolute`, 위치 기준 조상이 없다)이 가로 스크롤 칸 밖으로 빠져나가 문서 끝(883px)까지 간 것이다(PR #64 리뷰가 찾았다).
- 그러니 측정의 빈틈이 아니라 넘침 한 가지였다. 기록을 바로잡았다.

들여다보다 실제 결함을 찾았다. 넘친 페이지에서는 `innerWidth`·`innerHeight`가 같은 비율로 늘어나는데(844 → 1,911 등), 측정 두 곳이 이것을 화면 크기로 썼다.

- 표 열 측정: 표가 페이지 자체를 넘치게 하면, 늘어난 `innerWidth` 안에 열이 다 들어가 "390px 밖의 열 0"으로 셌다.
- 톤 지표(가장 많은 글자의 크기·15px 미만 글자 비율·강조색 글자 비율·무채색 면): "화면 여섯 장" 범위를 늘어난 `innerHeight`로 잡아 더 아래 글자까지 셌다(PR #64 리뷰가 찾았다).

## 2. 작업내용

- `measure.mjs`의 `clipProbes`: 화면 폭을 `document.documentElement.clientWidth`로 바꿨다. 이 값은 넘쳐도 390이다(viewport가 `width=device-width`일 때. 지난 실행 126개 페이지가 모두 그렇다).
- `renderMetrics`의 톤 지표: 여섯 장 범위와 면 넓이 상한을 `clientWidth`·`clientHeight`로 바꿨다.
- 고정 요소를 다루는 두 곳(끝까지 내렸을 때 고정 바가 글자를 가리는가, 캡처 전 고정 요소 옮기기)은 `innerWidth`·`innerHeight`가 맞아 그대로 두고 주석에 이유를 적었다. 넘친 페이지에서는 고정 요소가 늘어난 화면에 놓인다(하단 바 top 1,838 / innerHeight 1,911). `clientHeight`로 보면 그 바를 화면 밖으로 보고 캡처에서 숨긴다.
- 재현 페이지로 확인했다. 5열 표이고, 390px에서 오른쪽 두 열의 끝이 419·520px이다.

  | 재현 페이지 | 고치기 전 | 고친 뒤 |
  |---|---|---|
  | 표가 페이지 자체를 넘침(`innerWidth` 521) | 0 | 2 |
  | 같은 표를 가로 스크롤 칸 안에 둠 | 2 | 2 |
  | suta 없이 미용 예약 1번째(넘침, 고정 바) | 표 없음 — `overflow390` 참, 잘린 글자 0 | 같음 |

- 지난 실행 전체(`suta-gap`~`suta-gap7`, 126개 페이지)를 옛 기준과 새 기준으로 다시 셌다. 표 열은 직접, 톤 지표는 PR #64 리뷰가 셌고 바뀐 페이지는 직접 다시 쟀다.
  - 표 열: 표가 있는 페이지 28개(같은 파일 중복을 빼면) 중 바뀌는 페이지는 없다. 넘친 3개는 모두 표가 스크롤 칸 안에 있었다.
  - 톤 지표: 한 페이지만 바뀐다. 여섯 번째 묶음 suta 없이 집 소개 기사 2번째의 15px 미만 글자 비율이 22 → 25, 강조색 글자 비율이 1.5 → 1.6이다. 무채색 면은 바뀌는 페이지가 없다.
  - 그 값은 `evals/benchmark/gap6-web-results.json`에 옛 기준으로 남아 있다. 결과 파일은 잰 때의 기록이라 고치지 않았다. 문서에 이 값을 적은 곳은 없다.
- 기록 정정:
  - 연구 문서 14절과 여섯 번째 재측정 작업 기록의 "측정의 빈틈"을 원인(가로 넘침과 캡처 자르기)으로 고쳤다.
  - `docs/benchmark(.en).md`의 표 열 지표 설명에 화면 폭 기준을 더했다.

## 3. 주의사항

- 브라우저 안에서 도는 코드라 단위 테스트가 없다. 순수 판정 로직(`scripts/lib/clipCheck.ts`)은 바뀌지 않았다. 확인은 재현 페이지 3개, 지난 실행 126개 페이지, 바뀐 집 소개 기사 2번째의 재측정, 미용 예약 1번째 캡처에 하단 바가 남는지로 했다.
- 넘친 페이지의 390 캡처는 왼쪽 390px만 보인다. 실제 휴대폰은 페이지를 축소해 보일 수 있다. 판정은 잘린 캡처를 보고 "버튼이 보이지 않는다"고 했는데, 넘침이라는 같은 결함을 본 것이라 캡처 방식은 바꾸지 않았다.
- 화면 결과가 없는 측정 변경이라 화면 비교 이미지는 만들지 않았다(규칙 12).
