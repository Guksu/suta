## 1. 개요

PR #57~#60으로 0.17.0의 내용이 main에 모였다(빈 화면 유형 관례, 업종별 글꼴, 측정 보강, 요청 범위의 경계). 외부 개발자가 처음 보는 README와 상세 안내를 0.17 기준으로 맞추고, 릴리스 노트를 써서 릴리스를 발행한다. 노트 파일이 main에 들어가면 `.github/workflows/release.yml`이 검사를 다시 돌리고 `suta 0.17.0` 릴리스를 만든다.

## 2. 작업내용

- README 2벌
  - "무엇이 들어 있나"에 화면 유형 24종 관례와 업종에 맞춘 글자 크기·글꼴을 한 문장으로 넣었다.
  - 0.14 측정 표는 그대로 두고, 그 숫자가 네 요청을 0.14로 잰 것임을 분명히 적었다.
  - 새 절 "관례가 없던 화면 (suta 0.17)"을 더했다. 다섯 묶음의 판정 표, axe 0, 기사 화면 세 번 패배, 비용 1.2~3.3배, 다시 재지 않은 고침, 판정 모델의 한계를 담았다.
- 상세 안내 2벌: 우선순위 1에 요청 범위의 경계, 레이아웃 원칙 구성에 화면 유형 24종과 업종별 글꼴·`--font-serif`·`--font-mono`.
- `docs/releases/v0.17.0.md`: 변경 요약, 다섯 묶음의 판정 표와 불리한 결과(기사 세 번 패배, 비용), 다시 재지 않은 것, 설치·업데이트.

## 3. 주의사항

- 이 PR이 main에 들어가면 릴리스가 발행된다. 발행 뒤 릴리스의 태그·본문을 확인한다.
- 문서만 바꿨다. 화면 결과가 바뀌는 변경이 아니라 화면 비교 이미지는 없다(규칙 12). README의 새 절은 비교 문서의 묶음별 화면으로 이어진다.
- 0.14 비교 이미지(`docs/assets/benchmark-as-is-to-be.jpg`)는 바꾸지 않았다. 같은 네 요청을 0.17로 다시 재지 않았기 때문이다.
