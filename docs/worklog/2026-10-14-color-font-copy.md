## 1. 개요

사용자가 처음에 준 레퍼런스(국내 앱 31곳 화면 1,116장, 웹사이트 19곳, 디자인 피드백 사례)를 기준으로 색 조합·글꼴·문구를 개선하자고 했다. 지난번처럼 조사 → 개선 → 같은 요청으로 재측정 → 화면 비교 순서로 진행했다. 출처(서비스·사이트 이름)는 문서에 남기지 않는다(사용자 지시).

## 2. 작업내용

- **조사**(`docs/research/2026-10-14-color-font-copy.md`)
  - 색: 앱 화면의 평평한 면에서 강조색의 밝기·채도·색상각, 글자색의 온도를 쟀다. 레퍼런스 강조색은 OKLCH 밝기 중앙값 0.67·채도 0.18이었다. suta 0.6~0.11 산출물은 19개 중 12개가 어둡고 탁한 색이었다. 레퍼런스 글자색은 29곳 중 24곳이 순수 회색이었다.
  - 글꼴: 웹사이트 19곳 모두 웹폰트를 불러왔다. AI 산출물 48개는 하나도 불러오지 않았다.
  - 문구: 앱 화면 문구 7,539개를 역할별로 받아 적어 셌다. 오류·토스트·제목은 해요체가 76~87%였다. 일반 Claude는 22번 중 11번 개발용 문구를 화면에 남겼다.
- **토큰**: 무채색 다섯 값을 순수 회색으로 바꿨다(`#1b1e24` → `#1c1c1c` 등, 대비는 그대로). 패턴 CSS 폴백과 문서 예시도 같이 바꿨다. 글꼴 토큰 `--font-sans`(Pretendard → 운영체제 한국어 글꼴)를 더했다.
- **색 조합 도구**: `palette.ts`(테스트 15개)와 CLI `scripts/palette.mjs`. 강조색 하나에서 주 버튼 면·위 글자·강조 글자·선택 바탕·무채색을 만든다.
  - 흰 글자가 4.5:1이 안 되면 같은 색상각으로 어둡게 한다. 아주 밝은 색은 위 글자를 짙게 한다.
  - 탁한 색·파스텔을 진단하고 제안값을 낸다.
  - 대비는 반올림 없이 잰다. 첫 재측정에서 4.495:1이 4.5로 반올림돼 통과한 값을 axe가 4.49로 잡아, 고치고 테스트를 더했다.
  - 강조 글자를 선택 바탕(강조색 10%) 위에서도 4.5:1로 맞춘다. 두 번째 재측정에서 4.47:1이 나와 고쳤다.
- **문서**: `tone.md`에 강조색 맑기·색상각·무채색 온도·글꼴 절을 더했다. 새 `copy.md`에는 말투·버튼·대화상자·오류·빈 상태·토스트·제목·입력 안내·쓰지 않는 것을 적었다. SKILL.md에는 절차 4단계(색 한 벌·글꼴·문구), 금지선(글자·색·면 3행, 문구 표 7행), 값·체크리스트·한계를 더했다.
- **검사 규칙 5개**(`layout-audit`, TDD 테스트 14개, 규칙 16 → 21개)
  - `muddy-accent`: 어둡고 탁한 강조색 변수.
  - `neutral-temperature`: 따뜻한 강조색 옆의 푸른 회색.
  - `accent-contrast`: 한 파일에 함께 정의된 강조색 짝의 대비가 4.5:1 미만. 반올림 없이 잰다.
  - `meta-copy`: 화면에 남은 개발·데모 문구.
  - `mixed-tone`: 짧은 UI 문구의 해요체·합쇼체 섞임.
- **데모·패턴 문서**: 데모 안 앱 문구를 해요체로 고쳤다(파일 21개). 데모 강조색 간장색 `#8a4b1f`를 `#b4580f`로 바꿨다. 패턴 문서 예시 문구 7곳도 해요체로 고쳤다.
- **평가·버전**: 트리거 평가 2개(문구·색 조합 요청), 476/476. 버전 0.13.0. tests 배지 690.
- **재측정**(연구 문서 7절): 퍼블리싱 벤치마크 요청 6개를 suta 0.12와 0.13으로 두 번씩(조건마다 12번) 돌렸다. 0.12는 main 플러그인을 작업 트리로 따로 꺼내 실었다.
  - 강조색: 탁한 색 6 → 0, 맑은 색 1 → 8. 밝기·채도 중앙값 0.43·0.067 → 0.58·0.170.
  - 글자색: 푸른 회색 10 → 0(12번 모두 순수 회색).
  - 문구: 말투 섞인 실행 2 → 0, 짧은 문구의 합쇼체 10 → 1(요청문에 적힌 토스트 문구를 그대로 쓴 것).
  - 글꼴: 본문 글꼴 목록 맨 앞이 Pretendard인 실행 3 → 12. 파일은 두 조건 모두 불러오지 못했다(벤치마크가 외부 파일을 막는다).
  - axe 0 → 2곳. 하나는 선택 바탕 위 강조 글자(4.47:1, palette 빈틈), 하나는 네이버 초록 버튼 위 흰 글자(2.25:1, 관례를 따르지 않음).
  - 블라인드 판정(0.13 선택): 기본 모델 24번 중 11번, 다른 모델 24번 중 10번. 이유는 대부분 실행마다 갈리는 구성이었고, 색을 말한 7개 중 5개는 카페 화면의 짙은 갈색을 더 낫다고 봤다.
  - 비교 이미지 `docs/assets/color-font-copy-as-is-to-be.jpg`(각 조건의 첫 실행, 390 폭, 긴 화면은 위에서 1,220px), 화면 비교 문서 2벌에 절을 더했다.
- **재측정 뒤 고친 것**(다시 돌리지 않음)
  - palette가 강조 글자를 선택 바탕에서도 맞추고, `accent-contrast`가 그 짝도 잰다.
  - `tinted-surface`가 강조색 선택 바탕 변수(`--color-accent-soft`)와 채도 0.13 이상의 채운 색(카카오 노랑 버튼)을 세지 않는다. palette가 낸 값을 검사가 막고 있었다.
  - 제목 `text-wrap: balance`, 설명 문단 `text-wrap: pretty`(tone.md 5절·SKILL.md). 두 판정 모델이 모두 "제목 마지막 줄에 한 단어만 남는다"고 짚었다.
  - 화면 관례(로그인)에 "네이버 초록 면의 흰 글자 2.25:1, 초록은 로고에만"을 더했다.

## 3. 주의사항

- 벤치마크 하네스는 외부 파일을 막는다. 그래서 TO-BE도 글꼴 파일을 불러오지 않았다(이름만 적힘). 글꼴 불러오기 안내(`npm i pretendard`)가 실제 프로젝트에서 지켜지는지는 이 측정으로 확인하지 못했다.
- `accent-contrast`는 CSS 변수만 읽는다. Tailwind 클래스나 RN 토큰 객체의 강조색 짝은 보지 않는다.
- `mixed-tone`은 끝말만 본다. "~합니다"로 끝나는 홍보 문구, 번역투, 같은 대상의 다른 이름은 잡지 않는다.
- 블라인드 판정 기준에는 색·글꼴·문구를 따로 넣지 않았다(suta 규칙을 넣으면 suta 쪽으로 기운다). 그래서 이번 개선의 효과는 판정이 아니라 측정값으로 확인했다. 판정은 우열이 없었다.
- 판정 모델은 카페 화면에서 탁한 갈색을 "카페답다"고 골랐다. 레퍼런스(탁한 강조색 31곳 중 1곳, 커피 서비스는 초록·노랑) 쪽을 따라 규칙은 바꾸지 않았다. 사람 판정으로 다시 볼 만하다.
- 옵션 시트의 `nested-card` 경고(시트 안 칩·라디오를 상자 안 상자로 센다)는 이번 범위 밖이라 그대로 두었다.
- 재측정 뒤 고친 네 가지는 다시 돌려 확인하지 않았다.
- 원자료(캡처·받아 적은 문구·측정 JSON)는 세션 임시 폴더에만 있다.
