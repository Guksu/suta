## 1. 개요

PR #46(걷기 리워드 점검, 0.11.0)이 병합된 뒤 사용자가 두 가지를 요청했다. 하나는 증권 점검처럼 README 쪽에서 걷기 리워드 화면을 비교할 수 있게 하는 것이다. 다른 하나는 앞으로 요청하는 작업마다 화면 비교를 붙이는 것이다.

2차 실행은 배포 전 스냅숏으로 돌려서, 축하 화면이 지금 패턴(금색 원판 트로피)과 달랐다. 사용자가 배포판 0.11.0으로 suta를 다시 돌려 비교 이미지를 만들기로 정했다. 규칙은 작업 크기에 따라 둘 곳을 나누기로 정했다.

## 2. 작업내용

- **브랜치**: 지정 브랜치 `feat/busy-bohr-1pb1xb`를 최신 main(5850aff) 위로 옮겼다. 병합된 이력만 있던 브랜치다.
- **3차 실행(suta 0.11.0 ×2)**: main의 `.claude-plugin`·`skills`를 스냅숏으로 떠서 1·2차와 같은 요청문·조건으로 돌렸다.
  - 4.7분·0.98달러, 8.9분·1.62달러. 두 실행 모두 빌드 통과, 모델은 1차와 같다.
  - axe 5·0, 이모지 0, 쉬는 화면 무한 반복 0, 축하는 대화상자(금색 원판 트로피, 포커스 "확인").
- **3차 판정(48번)**: 일반 1·2 ↔ suta 0.11.0 1·2. 기본 모델 20:4, 다른 모델 20:4.
  - 일반 조건을 선택한 4회는 모두 첫 짝의 축하·순위다. 판정 모델은 전용 축하 페이지와 시상대를 골랐다.
  - suta 쪽의 지적: 축하 뒤 홈의 다음 단계 문구, 하단 고정 내 순위 행이 목록 끝을 가림.
- **비교 이미지** `docs/assets/walking-as-is-to-be.jpg`(1848×1432, 323KB)
  - 위 줄은 일반 1번째 실행, 아래 줄은 suta 0.11.0 1번째 실행이다. 390 첫 화면 6개다.
  - 잘 나온 실행을 고르지 않았다. 일반 조건이 선택된 축하·순위 화면도 포함했다.
  - 이커머스 이미지와 같은 틀(칸 폭 290, 옅은 회색 바탕, 줄 머리 AS-IS·TO-BE만).
- **화면 비교 문서 2벌**: 증권 절 뒤에 "모바일 웹앱: 걷기 리워드(게이미피케이션)" 절. 요청문, 이미지, 실행 수, 표(axe·이모지·축하·무한 반복·포커스·배지·시간·비용), 3차 판정과 선택 이유, 1·2차 판정, 연구 문서 링크.
- **연구 문서**: 6절 제목을 "3차에서 확인"으로, 7절 "3차 결과 — suta 0.11.0(배포판)"을 더하고 한계를 8절로 옮겨 고쳤다.
