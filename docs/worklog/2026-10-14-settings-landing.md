## 1. 개요

앞선 작업(색 조합·글꼴·문구, 0.13.0)의 비교 이미지를 본 사용자가 "TO-BE의 설정 화면과 일정 관리 SaaS 랜딩은 아직 AI 슬롭 느낌이 난다"고 했다. 사용자는 레퍼런스 사이트를 더 분석하고, 레퍼런스 사이트만이 아니라 시중에서 많이 쓰는 웹·앱도 참고해 개선하라고 했다. 조사 → 개선 → 같은 요청으로 재측정 → 화면 비교 순서로 진행했다. 출처 이름은 문서에 남기지 않는다.

## 2. 작업내용

- **진단**: 일반 Claude 2번, suta 0.6·0.12·0.13 각 2번의 설정·랜딩을 나란히 놓았다. 설정은 8번 모두 같은 틀이었다. 옅은 바탕 + 흰 둥근 묶음, 프로필 카드, 설명 줄이 붙은 스위치, 목록 안 테마 세그먼트였다. 랜딩도 8번 모두 같은 틀이었다. 좌우 히어로에 몇 줄짜리 제품 카드, 그 아래 번호 목록이나 아이콘 카드, 요금·FAQ 순이었다. suta는 색·글자만 바꾸고 틀은 그대로 두었다.
- **설정 레퍼런스**(연구 문서 2·3절)
  - 디자인 레퍼런스 사이트의 앱 31곳에서 화면 전체 목록(약 14,000장)을 다시 받았다.
  - 8장마다 1장을 시트로 훑어 설정류 화면 202장을 골랐고, 필터로 16장을 더했다.
  - AI 화면 8장(이름 가림)과 함께 같은 형식으로 기록했다. 설정류는 161장(30곳)이었다.
- **랜딩 레퍼런스**(연구 문서 2·4절)
  - 시중 SaaS·서비스 46곳 중 robots.txt가 허용한 42곳(국내 14곳)을 1440·390px에서 끝까지 찍었다.
  - 계산된 스타일을 쟀고, AI 랜딩 8개(이름 가림)와 함께 같은 형식으로 기록했다.
- **반영**
  - `screen-conventions.md` 설정·마이 절을 실측으로 다시 썼다.
    - 폭 가득 흰 목록이 기본이다(30곳 중 26곳).
    - 스위치는 켜짐 강조색(18곳 중 16곳), 꺼짐 옅은 회색(89%)이다.
    - 설명 줄은 낯선 행에만 둔다.
    - 테마·언어는 "현재 값 + 꺾쇠" 행이다.
    - 고객센터·약관·버전 행을 두고, 첫 화면은 8행 안팎이다.
  - 같은 문서의 랜딩 절도 다시 썼다.
    - 측정표와 뼈대(히어로 → 증거 → 기능 구역마다 제품 화면 → 후기 → 요금·FAQ → 마지막 띠)를 넣었다.
    - 제품 화면 충실도와 지어낸 회사 글자 로고를 적었다.
    - "번호 + 제목 한 열로 충분"이라는 문장을 뺐다. 01·02·03 목록은 이 문장에서 나왔다.
  - `tone.md`·`SKILL.md`: 스위치가 있는 앱 화면은 근거가 없어도 맑은 강조색을 정한다는 예외를 더했다. 랜딩은 주 버튼이 거의 검정이어도 된다(42곳 중 10곳).
  - `switch` 패턴
    - 켜짐: `--color-accent`를 따른다(없으면 #1c1c1c).
    - 꺼짐: 옅은 트랙(#e5e5e5)에 1px #8a8a8a 테두리를 둔다. 흰 바탕 대비 3.45:1로 비텍스트 기준은 그대로 지킨다.
  - `SKILL.md`: 금지선 2행(설정·랜딩), 체크리스트 2항목, 검사 체크 항목에 `numbered-markers`를 더했다.
  - `layout-audit` 규칙 `numbered-markers`(TDD, 테스트 3개, 규칙 21 → 22개)
    - 기능 목록의 01·02·03을 잡는다.
    - 01~09가 7개 이상이면 월·시 목록이라 뺀다.
    - 처음에는 "10 이상이 있으면 뺀다"로 짰다. 그 조건 탓에 히어로 달력의 날짜 칸(13·14) 때문에 실제 번호 목록을 놓쳐서 고쳤다.
    - 결과: suta 0.6~0.13 랜딩 6개를 모두 잡고, 일반 Claude 랜딩·다른 화면·스킬·데모에서는 0건이다.
  - 데모 ⑦ 설정(규칙 12, 전후 캡처 `docs/worklog/assets/2026-10-14-settings-demo.jpg`)
    - 데모의 "고친 뒤"가 바로 둥근 묶음이었다. 이를 폭 가득 목록으로 바꿨다.
    - 설명 줄은 하나만 남기고, 화면 테마·고객센터·약관·버전 행을 더했다.
    - 로그인 예시가 같은 클래스를 써서 설정 전용 클래스(`.lp-t-settings`)로 나눴다.

- **재측정**(연구 문서 6절): 같은 설정·랜딩 요청을 0.13 3번, 0.14 세 차례(설정 6번, 랜딩 9번) 돌려 재고 블라인드 판정했다.
  - 1차(0.14 첫 판): 설정은 모두 폭 가득 목록·강조색 스위치·꺾쇠 행 테마가 됐다. 랜딩은 구역 6\~7개, 후기 5\~7개, 번호 목록 0이 됐다. 판정은 6 : 6(설정 2 : 4, 랜딩 4 : 2)이었다.
  - 1차 뒤 고친 것
    - 설정: 예시 스위치가 모두 켜져 있었다 → "켜짐·꺼짐을 섞는다". 목록 아래가 회색으로 비었다 → "흰 면으로 잇는다". 테마 행은 바텀시트에서 고르게 했다. 넓은 화면의 흰 열을 바탕에서 띄웠다.
    - 랜딩: 제품 화면 그림 안에 진짜 버튼이 있어 axe `nested-interactive`가 났다 → 그림은 `role="img"`로 표시하고 안은 모양만 그린다. 검사 규칙 `interactive-in-picture`(error)를 TDD로 더했다(테스트 2개, 규칙 23개). 그림 안 상자는 `nested-card`로 세지 않는다. 벤치마크 측정(`measure.mjs`)도 그림 안 상자를 세지 않게 고쳤다.
  - 2차: 판정 4 : 8(설정 2 : 4, 랜딩 2 : 4). 랜딩은 진짜 흠으로 졌다. 모바일에서 주간 달력 그림이 390px에 눌려 글자가 잘리고 겹쳤다. 데스크톱에서는 그림이 오른쪽 끝에서 잘렸다. 관례의 "가장자리에서 잘려 더 있다는 느낌", "모바일에서는 잘라 보인다"가 만든 흠이었다.
  - 2차 뒤 고친 것: 제품 화면 그림은 컨테이너 안에 다 들어간다. 모바일에는 한 열짜리 그림(오늘 일정·목록 한 칸)을 따로 그린다. 체크리스트에도 한 줄 더했다.
  - 3차(랜딩만): 3번 모두 모바일에 오늘 하루 목록을 그렸고, 그림 안 잘린 글자는 0이었다. 판정은 두 모델 모두 6 : 0이었다.
  - 3차 뒤 고친 것: 2·3차의 접근성 위반은 대부분 #8a8a8a 같은 옅은 회색 글자(글자 로고·그림 안 시각)였다. 증거 띠 관례에 "글자 로고도 대비 4.5:1, 옅은 글자색보다 옅게 하지 않는다"를 더했다. 이 문장 뒤로는 다시 돌리지 않았다.
  - 설정은 판정을 따라 되돌리지 않았다. 판정 모델은 둥근 카드 묶음·스위치마다 설명·테마 세그먼트·요청한 항목만 있는 0.13을 골랐다. 이 틀이 레퍼런스 30곳과 반대이고, 사용자가 AI 슬롭이라고 한 그 틀이다.
  - 비교 이미지 `docs/assets/settings-landing-as-is-to-be.jpg`: 위 0.13 첫 실행, 아래 0.14(설정은 2차, 랜딩은 3차 — 각 관례를 마지막으로 고친 뒤의 첫 실행). 왼쪽부터 설정 390, 랜딩 390(위 2,000px), 랜딩 1440 전체.

## 3. 주의사항

- 레퍼런스 설정 화면은 8장마다 1장을 본 시트에서 골랐다. 놓친 설정 화면이 있고, 행 높이·띠 높이는 캡처를 보고 추정한 값이다. 캡처는 2023년 무렵 화면이다.
- 랜딩 캡처는 지연 로딩·쿠키 창·팝업 때문에 절반 이상이 일부 비어 보였다(`partial`). 데스크톱 전체 캡처는 10,000px에서 잘랐다.
- 지어낸 회사 이름의 글자 로고를 증거 띠에 쓰도록 안내했다. 실제 회사 이름·로고는 쓰지 않는다.
- 스위치 꺼짐 트랙을 옅게 하면서 1px 테두리로 3:1을 지켰다. 테두리를 지우려면 서비스가 다른 방법으로 상태를 알려야 한다.
- 0.13을 한 번 더 돌릴 때는 작업 전 저장소를 통째로 복사해 둔 사본(`/home/user/suta-bench/snap-013`, 저장소 밖)을 썼다.
- 원자료(캡처·기록·측정 JSON)는 세션 임시 폴더에만 있다.
- 블라인드 판정은 조건당 3번뿐이다. 판정 모델 하나는 화면 생성 모델과 같다. 설정에서는 판정 모델이 AI가 흔히 만드는 틀(둥근 카드 묶음·세그먼트)을 골랐다. 판정 숫자만으로 "AI 티"를 잴 수는 없다.
- 0.13의 세 번째 랜딩은 스크롤하면 나타나는 효과 탓에 찍은 화면에서 히어로 아래가 비어 보였다. 2·3차 판정에 모두 이 쌍이 들어 있다. 3차는 이 쌍을 빼도 4 : 0이다.
- 마지막에 더한 증거 띠 대비 문장은 다시 돌려 확인하지 않았다.
