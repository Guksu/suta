# 측정: 칸 밖으로 잘린 글자와 첫 화면 밖의 표 열

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-11-06 |
| 작성 | Claude Code |
| 관련 경로 | `scripts/lib/clipCheck.ts`, `demo/src/tests/clipCheck.test.ts`, `scripts/benchmark/measure.mjs`, `scripts/benchmark/report.mjs`, `docs/benchmark(.en).md` |

## 1. 개요

재측정 네 번에서 사람이 캡처를 보고 찾은 결함 두 가지를 측정 스크립트가 세지 못했다. 1280px에서 큰 금액이 지표 칸 밖으로 나간 것과, 390px에서 표를 가로로 넘기게 두어 매출 열이 첫 화면 밖에 남은 것이다. 판정은 두 결함을 반복해서 짚었다. 이것을 숫자로 세게 하고, PR #57 리뷰에서 나온 "결과 JSON에 생성 비용이 없다"도 함께 고쳤다.

## 2. 작업내용

- `scripts/lib/clipCheck.ts`(순수 로직, 테스트 15개를 먼저 씀)
  - `clippedTexts`: 글자가 잘라내는 칸(`overflow-x: hidden·clip`)이나 테두리·바탕이 있는 가장 가까운 칸의 좌우 끝을 넘으면 센다. 말줄임, 1px 칸(sr-only), 칸 밖에 통째로 있는 글자(캐러셀의 다음 장·접힌 칸), 1px 이내 차이는 뺀다.
  - `hiddenColumns`: 표 첫 줄의 칸 중 보이는 폭을 넘는 칸의 수.
- `measure.mjs`: 브라우저에서 글자·표의 상자 좌표만 모으고(`clipProbes`) 판정은 위 로직에 넘긴다. 390과 1280에서 글자를, 390에서 표를 본다. 가로 스크롤 칸 안의 글자와 `clip`·`clip-path`로 숨긴 글자는 탐침 단계에서 뺀다. 결과 필드 `clippedText390`·`clippedText1280`(잘린 글자 앞 40자)·`hiddenTableColumns`.
- `report.mjs`: 표에 두 줄("칸 밖으로 잘리거나 삐져나온 글자가 있는 화면", "390px 첫 화면 폭 밖에 표 열이 남은 화면"). 이 값을 잰 `metrics.json`에서만 싣는다 — 예전 측정에 0/n으로 찍히면 결함이 없었던 것처럼 읽힌다. 조건마다 생성 비용(`costUsd` 합계·중앙값)과 실행마다 비용을 결과 JSON에 남긴다.
- 확인: 지난 웹 실행 24개(SaaS 리포트·쇼핑몰 매출 리포트·도서관 통계·앨범 리뷰)의 사본을 다시 쟀다.
  - 1280 잘림은 판정이 짚은 두 건만 잡혔다 — suta 0.17 SaaS 리포트 1번째의 "758,071,300원", suta 없이 2번째의 "₩304,170,000".
  - 표 열은 도서관 통계의 suta 없이 3번 모두 4열, suta 3번 모두 0(카드 목록), 쇼핑몰 매출 리포트의 suta 3번 3~5열.
  - 처음 판에서 나온 오탐(가로 스크롤 표 안의 숫자, 화면 낭독용 숨긴 글자 "증가"·그래프 설명)은 위 제외 규칙으로 없앴다.

## 3. 주의사항

- 측정 도구만 바꿨다. 화면 결과가 바뀌는 변경이 아니라 화면 비교 이미지는 없다(규칙 12).
- 가로로 넘기는 칩 줄·메뉴가 화면 끝에서 잘려 보이는 것은 세지 않는다(가로 스크롤 칸 안이라). 정지 화면의 판정은 이것도 "잘림"으로 본 적이 있다.
- 세로로 잘린 글자(줄 수 제한)와 SVG 안 글자가 그래프 칸을 넘는 경우는 좌우 끝만 보므로 일부만 잡는다.
- 지난 결과 JSON(`evals/benchmark/gap*-results*.json`)은 다시 만들지 않았다.
