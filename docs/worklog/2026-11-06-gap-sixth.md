## 1. 개요

다섯 번째 묶음 뒤에 고친 것이 있었다. 가로 줄의 첫 항목 정렬, 데스크톱 작성 폼, 기사 표현, 요청 범위의 경계와 사이트 메뉴 이름(PR #59·#60)이다. 이 고침들은 아직 다시 재지 않았다. 그래서 업종이 다른 새 요청 3개로 두 조건을 3번씩, 모두 18번 돌렸다. 기준은 `segmented-control` 고침(PR #62)까지 들어간 main(`147413e`)의 스냅숏이다. 요청문은 `evals/benchmark/gap6-app-prompts.json`·`gap6-web-prompts.json`에 있다.

## 2. 작업내용

- 실행과 측정 18번, 캡처 18개를 눈으로 확인했다(결함 없음). 이어 두 모델로 블라인드 판정 36번을 돌렸다. 생성 비용은 20.48달러다.
- 판정(suta : 없이, 기본 모델·다른 모델):

  | 요청 | 기본 모델 | 다른 모델 |
  |---|---|---|
  | 미용 예약 | 4 : 2 | 3 : 3 |
  | 채용 공고 | 5 : 1 | 2 : 4 |
  | 집 소개 기사 | 6 : 0 | 4 : 2 |

  두 모델을 합치면 처음으로 세 요청 모두 suta가 앞섰다(24 : 12). 채용 공고는 다른 모델에서 졌다.
- 확인된 고침:
  - 기사 관례: 드롭캡·번호 소제목·가운데 제목 묶음, 메뉴 4개와 모바일 메뉴 버튼. 여행 기사 0 : 6, 0 : 6에서 이번 6 : 0, 4 : 2가 됐다.
  - 가로 줄 정렬: suta 3번 모두 날짜 줄의 첫 칸이 본문 정렬선에 있었다.
  - 세그먼트: 채용 공고 3번 모두 정본 세그먼트를 썼다. 그런데도 레이아웃 속성을 움직인 화면은 0/3이다.
- 진 이유와 고침(다시 재지 않음):
  - 데스크톱 작성 폼의 배치. 진 판정 5번 모두가 짚었다. 입력 열과 패널 사이가 크게 비었거나, 머리보다 좁은 본문이 왼쪽에 붙었다.
    - 고침: 입력 열과 패널을 24~32 간격의 한 묶음으로 가운데에 두고, 머리·제목과 같은 최대 폭을 쓴다(화면 관례·확인 목록).
  - 아무것도 고르지 않은 세그먼트가 비활성처럼 보였다.
    - 고침: 세그먼트는 한 칸이 늘 골라져 있다. 기본값이 없는 필수 선택은 테두리 칩이다(화면 관례·확인 목록·`segmented-control` 주의사항).
  - 회색 바탕·흰 패널·회색 채움 칸이 겹쳐 칸이 흐렸다.
    - 고침: 그 경우에는 1px 테두리 칸을 쓴다(화면 관례).
  - 미용 예약의 금액 구역이 안내 문장 한 줄뿐이었다. 진 판정 5번 모두 상대의 금액이 든 하단 고정 바를 들었고, 4번은 항목별 금액 내역도 들었다.
    - 고침: 금액이 있는 예약·신청 폼은 항목별 내역 + 금액이 든 하단 고정 바를 둔다. 요청한 내용을 보이는 방식이라 요청 범위 안이다(화면 관례·확인 목록).
  - 반려견 아바타로 쓴 `art--pet`이 "곰 모양"으로 읽혔다.
    - 고침: 종이 정해진 자리나 64px 이하 원형 아바타에는 이름 첫 글자 원을 둔다(화면 관례).
- 기록:
  - 연구 문서 14절과 한눈에 요약.
  - 화면 비교 문서 2벌의 맨 앞 절과 비교 이미지(각 조건의 첫 실행).
  - README 2벌의 "관례가 없던 화면" 절(여섯 묶음, 99번 실행, 판정 합계).

## 3. 주의사항

- 조건마다 3번이고, 판정 모델 하나는 생성 모델과 같다.
- 채용 공고는 판정 모델에 따라 결과가 반대였다. 다른 모델은 상대의 파란 주 버튼과 테두리 입력칸을 "위계가 분명하다"고 두 번 골랐다. 강조색은 suta의 색 기준이라 바꾸지 않았다.
- 기사에서 진 2번은 상대의 종이색 바탕과 명조 부제를 골랐다. 취향 쪽이라 고치지 않았다.
- 화면 비교 이미지는 벤치마크 결과라 `docs/assets/`에 두었다(규칙 12). 관례 고침은 문서만 바꿔 데모 화면은 그대로다.
