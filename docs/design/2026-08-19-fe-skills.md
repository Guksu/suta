# 설계: suta (구 fe-skills) — AI 슬롭 없는 UI를 위한 설치형 에이전트 스킬

| 항목 | 내용 |
|------|------|
| 최종 갱신 | 2026-10-07 |
| 상태 | 승인됨 (2026-08-19) |
| 참여 | 사용자(Guksu) · harness 스킬 |

## 1. 목표와 완료 기준

**AI 슬롭(AI가 만든 티가 나는 UI)을 없애는 설치형 에이전트 스킬** (9라운드에서 전환). 사용자가 진입 스킬 `suta` 하나를 한 번 설치하면, Claude Code·Codex 등이 UI 요청마다 그 스킬을 자동으로 읽는다. 진입 스킬은 AI 슬롭 금지선(레이아웃·모션·상호작용·접근성)과 패턴 카탈로그를 담고, 패턴 55종은 필요할 때만 읽힌다. Claude Code·Codex 플러그인으로 설치하면 파일을 고칠 때마다 레이아웃·모션 검사 훅이 돈다(10라운드). 훅은 이번 편집이 바꾼 줄만 판정하고, 화면을 짤 때는 잘 만든 앱에서 뽑은 화면 유형별 뼈대에서 시작한다(11라운드).
각 패턴은 (1) 사용 방법 (2) 사용 예시 코드 (3) 사람이 눈으로 확인하는 UI 데모를 갖춘다.

**패턴 1건의 완료 기준(게이트):** ① demo 빌드·린트 통과 ② 구조 검증(frontmatter·링크·카탈로그 동기)과 선택 평가 통과 ③ 브라우저에서 데모 실동작 확인(스크린샷/녹화) ④ fe-craft 모션 리뷰(이징·타이밍·reduced-motion) 통과 ⑤ 워크로그 기록.
**첫 릴리스 완료 기준(2026-08-19, 달성):** 스킬 1~2개가 위 게이트를 통과하고, 플러그인이 마켓플레이스로 설치 가능하며, 데모 사이트가 GitHub Pages에 배포됨.

## 2. 범위

아래는 2026-08-19 첫 릴리스의 범위다. 9라운드 전환의 범위는 기존 패턴을 진입 스킬 하나로 재구성하는 것까지였다. 10라운드에서 레이아웃(원칙·토큰·정적 검사)과 편집 후 검사 훅을 넣었다. 11라운드에서 디자인 레퍼런스 분석으로 화면 유형별 관례를 더하고, 훅이 바꾼 줄만 판정하게 했다. 13라운드에서 글자·색·면 기준(색 역할 토큰)을 더했다. 프로젝트에 디자인 체계가 있으면 그것을 따르고, 없을 때만 이 기본값을 쓴다. 렌더가 필요한 검사(글자 대비·누르는 영역·좁은 폭 넘침)도 범위 밖이다.

**포함:**

- 플러그인 골격(marketplace.json·plugin.json) + 첫 스킬 2개: enter-exit(진입/퇴장), scroll-reveal(스크롤 리빌) — 문서+references+assets 예시 컴포넌트
- Vite+React 데모 SPA(스킬별 데모 페이지, assets 컴포넌트 import 렌더링) + GitHub Pages 배포(Actions)
- 하네스(라이트): 도메인 스킬 1개(스킬 추가 파이프라인) + 훅·권한 + 템플릿 2종 + CLAUDE.md 포인터

**제외:**

- npm 패키지 배포, Storybook, 저장소 분리
- 에이전트 정의·오케스트레이터(풀 티어 산출물 — 대량 작업이 생기면 확장 분기로 승격)
- 애니메이션 카테고리 전체 커버(첫 릴리스는 구조 검증용 1~2개만)

## 3. 시스템 구조

- 저장소: https://github.com/Guksu/suta (2026-10-06 fe-skills에서 이름 변경)
- 착수 시점 상태(2026-08-19): 빈 디렉토리, 커밋 0건
- 사용자 컨벤션(기존 단일 출처): useCallback/useMemo 지양, 화살표 함수, named-object 인자, useEffect 명명, TDD 우선, 한글 조판 word-break: keep-all

**저장소 레이아웃 (2라운드 확정, 9라운드 재구성):**

```
suta/                                # 저장소 = 마켓플레이스 = 플러그인(source "./") = 스킬 이름
├─ AGENTS.md                         # 모든 코딩 에이전트 공통 작업 지침(단일 출처) — 8라운드
├─ CLAUDE.md                         # Claude Code 전용 보충(@AGENTS.md 가져오기)
├─ .claude-plugin/
│  ├─ marketplace.json               # Claude Code 마켓플레이스 — 플러그인 suta 1개
│  └─ plugin.json                    # 플러그인 정보(이름·버전) + 편집 후 검사 훅(인라인) — 10라운드
├─ .codex-plugin/plugin.json         # Codex 플러그인 정보 — skills "./skills/" + 편집 후 검사 훅(인라인) — 10라운드
├─ .agents/plugins/marketplace.json  # Codex 마켓플레이스(local "./") — 10라운드
├─ skills/suta/                      # 설치되는 진입 스킬 — 9라운드
│  ├─ SKILL.md                       # UI 요청에 걸리는 description + 작업 절차·AI 슬롭 금지선·레이아웃·모션 값 + 패턴 카탈로그(생성)
│  ├─ scripts/                       # 통합 검사(audit.mjs)·편집 후 검사 훅(post-edit-hook.mjs) — 10라운드
│  └─ patterns/{pattern-name}/
│     ├─ PATTERN.md                  # 정본: 사용 방법·사용 예시 (SKILL.md가 아니어야 패턴이 별도 스킬로 등록되지 않는다)
│     ├─ references/                 # 상세 문서
│     └─ assets/                     # 예시 컴포넌트 코드 (정본의 일부)
├─ .agents/skills/add-skill/         # 패턴 추가 파이프라인(metadata.internal) — .claude/skills/add-skill은 심볼릭 링크
├─ demo/                             # Vite+React SPA — 패턴 데모, 설치 안 됨
│  └─ src/demos/{pattern-name}/      # skills/suta/patterns/*/assets/를 import해 렌더링
├─ evals/                            # 선택 평가 — trigger.json(진입 스킬)·selection/(패턴)
├─ scripts/                          # 검사·선택 평가·카탈로그 생성·설치(install-skills.sh)
└─ docs/                             # 설계·워크로그
```

- 진입 스킬 하나로 묶은 이유(9라운드): 스킬 53개가 각자 description으로 경쟁하면 일반 UI 요청("로그인 화면 만들어줘")에는 아무것도 걸리지 않는다. 또 스킬 목록 길이 예산(Claude Code는 컨텍스트의 1%, Codex는 2%)을 넘어 덜 쓰인 스킬부터 목록에서 빠진다. 진입 스킬 1개가 넓게 걸리고 패턴은 필요할 때만 읽는 구조(점진적 공개)로 바꿨다 — impeccable과 같은 방식.

- 데모는 GUI 쇼케이스 — 스킬 문서(및 assets/ 예시 코드)가 정본, 데모 앱은 그 코드를 import해 보여주기만 한다(복사본 금지)
- 기술 기준: CSS 우선, CSS로 어려운 것만 라이브러리(motion 등) — 스킬마다 "왜 이 기술인가" 한 줄 명시
- 프레임워크 지원(5라운드): assets = 바닐라 코어(.ts, 의존성 0) + React 래퍼(.tsx) 2층. 순수 JS·React 프로젝트 모두 사용 가능해야 한다
- 데모 배포: GitHub Pages (GitHub Actions, main 푸시 시 자동)

## 4. 실행 방식과 역할

- **실행 모드: 직접 실행** — 반복 작업이 "스킬 추가"(문서→데모→검증) 순차 흐름 하나뿐. 병렬화·협상 요소 없음 → 사다리 0단.
- **티어: 라이트** — 도메인 스킬 `add-skill`(가칭) 1개 + 훅·권한 + 규칙 파일 + 템플릿 2종(worklog·handoff). 에이전트 정의·오케스트레이터는 만들지 않는다.
- UI 구현·수정 시 `fe-craft`(모션 리뷰·디자인 비평), 데모 사이트 배포 전에는 `fe-predeploy`를 연결한다.

## 5. 안전장치와 권한

- 보호 브랜치: **main**. 작업은 feat/{skill-name} 브랜치에서(branchGuard 훅).
- PR 플로우 **옵트인 활성**(allowCommitPush=true): 사용자가 명시 요청 시에만 커밋·푸시·PR 생성(pr 스킬, PR 베이스 main). 머지·rebase·force push는 사용자 전담. 커밋·PR에 Claude 작성 표기 금지(훅 차단).
- 훅 3종: git 변경 차단 · 시크릿 접근 차단 · 보호 브랜치 편집 차단 + 시크릿 deny 권한.
- 검증 게이트는 §1 완료 기준 참조. 단위 테스트는 로직 있는 예시(상태 전이·제스처)에만 적용 — 순수 시각 애니메이션에 빈 테스트를 양산하지 않는다.
