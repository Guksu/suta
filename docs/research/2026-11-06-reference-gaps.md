# 레퍼런스 재분석 — suta가 아직 다루지 않는 화면 유형

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-11-06 |
| 계기 | 사용자 — "몇 번 써 보니 아직 AI 슬롭 형태의 디자인이 많이 나온다. 처음 준 레퍼런스를 더 심층 분석하고, 구현되지 않은 유형의 레이아웃이 무엇인지 브리핑해 달라" |
| 자료 | ① 처음 받은 디자인 레퍼런스 사이트(앱·웹 화면 아카이브)의 공개 분류와 패턴 페이지. ② 같이 받은 웹 디자인 어워드 사이트의 최신 선정작 목록 1쪽(60개). 서비스·사이트 이름과 화면 이미지는 저장소에 남기지 않는다 |
| 상태 | 1단계(재분석) 결과. 2단계(진단 실행)와 3단계(관례 보강)는 이어서 한다 |

## 1. 한눈에

- **suta 관례는 레퍼런스 흐름의 앱 40%, 웹 7%만 덮는다**(항목 수 가중). 일부만 덮는 흐름이 각각 33%·35%다. 웹은 레퍼런스 256곳 중 비즈니스툴이 70곳으로 가장 많은데, suta의 웹 관례는 SaaS 랜딩·대시보드·증권뿐이다.
- **관례가 없는 큰 흐름**: 앱은 생성하기·신청하기·기획전·통계·글쓰기·취소하기·멤버십, 웹은 탐색·생성하기·내역·필터·마이페이지·통계다.
- **빈 흐름 17개의 공개 화면(51개 흐름·293장)에서 여러 패턴에 되풀이된 것**(4.1절)
  - 고르기·확인·필터는 하단 시트, 필수 입력 전 주 버튼 비활성
  - 완료는 토스트가 아니라 다음 할 일을 알리는 창
  - 숫자는 하나를 크게 + 뜻을 문장으로, 지표 카드 4개 줄은 0
  - 숫자·날짜는 앱이 그린 키패드·휠·드롭다운, 빈 데이터는 구역을 숨기지 않음
- **지금 suta 관례와 부딪히는 곳이 있다.** 대시보드 관례의 "지표 3~4개 + 흰 데이터 카드"는 0.14 결과에서 그림자 없는 카드 4개 줄이 됐다. 레퍼런스 대시보드·통계 6개 흐름에는 카드 4개 줄이 없었다(6절).
- **웹 디자인 어워드 선정작 60개의 첫 화면**은 사진·영상 35%, 큰 글자 25%, 브랜드색 면·그림 25%다. suta 랜딩 관례의 "히어로에 제품 화면"은 5%다. SaaS 랜딩(앞선 조사 42곳 중 55%)에는 맞지만, 브랜드·기업 사이트에는 관례가 없다.
- 표본은 패턴마다 흐름 3개다. 관례라기보다 "잘 만든 화면에서 본 방식"이고, 2단계 진단으로 AI 결과와 대어 본다.

## 2. 방법과 한계

### 자료

- **앱·웹 화면 아카이브**
  - 지난 조사(2026-10)에는 로그인 없이 앱 31곳만 보였다. 지금은 공개 분류에 앱 594곳·웹사이트 256곳이 있다. 패턴(흐름 유형) 분류 62개마다 항목 수가 로그인 없이 보인다.
  - 항목 수는 "그 흐름이 기록된 횟수"다. 앱 항목 19,114개(유형으로 볼 수 없는 "iPhone 스크린샷"·"기타" 876개 제외), 웹 항목 9,046개(같은 기준).
  - suta에 관례가 없거나 일부만 있는 흐름 중 큰 것 17개(앱 11·웹 6)의 공개 패턴 페이지를 브라우저로 열었다. 로그인 없이는 패턴마다 최신 흐름 3개만 보인다. 흐름마다 화면 2~31장, 모두 51개 흐름·약 290장이다. 에이전트 5개가 같은 형식으로 기록했다(→ 4절).
  - 사이트 안의 데이터 요청을 직접 부르지 않고, 사람이 보듯 페이지를 열고 끝까지 스크롤해 캡처했다. 페이지 사이에 6초 이상 쉬었다. robots.txt가 막은 경로(`/admin`·`/user/`·`/layout/` 등)는 열지 않았다.
- **웹 디자인 어워드 사이트**
  - robots.txt가 검색 엔진 밖의 자동 수집을 막는다. 사용자의 요청으로 선정작 목록 1쪽만 브라우저로 열었다. 개별 선정작 사이트는 열지 않았다.
  - 목록의 썸네일(첫 화면) 60개를 직접 분류했다(→ 5절).
- 원자료(캡처·조각 이미지)는 세션 임시 폴더에만 두었다.

### 한계

- **패턴마다 흐름 3개뿐이다.** "관례"는 3개 중 2개 이상, "흔한 선택"은 3개 중 1개다. 항목 수가 수백인 패턴도 3개만 봤고, 한 서비스가 흐름 여럿을 차지한 패턴이 있다(기획전·이벤트는 3개 모두 금융 1곳, 웹 내역은 비즈니스툴 1곳). 그래서 4절은 관례라기보다 "잘 만든 화면에서 본 방식"이다.
- 캡처할 때 사이트 위에 고정된 막대가 일부 화면 아래쪽을 가렸다. 가려진 곳은 기록에서 "확인 못 함"으로 남겼다.
- 표본에 없던 것: 날짜·시간을 고르는 예약(예약·결제 3개는 주식 주문·커머스 결제였다), 유료 구독 요금제(멤버십 3개는 모두 실적 등급), 커머스 상품 탐색(웹 탐색 3개는 블로그·시세).
- 패턴 분류는 아카이브가 붙인 것이다. 한 흐름이 여러 패턴에 걸리고, suta의 화면 유형과 경계가 다르다. 대응(3절)은 사람이 판단했다.
- 어워드 사이트는 첫 화면 썸네일만 봤다. 아래쪽 구성과 상호작용은 보지 않았다.
- 화면 생성 실험은 이 단계에서 하지 않았다(2단계에서 한다).

## 4. 빈 유형의 관례 — 패턴 페이지 기록

패턴마다 흐름 3개다. "3/3"은 세 흐름 모두, "2/3"은 둘에서 봤다는 뜻이다. "AI가 틀리기 쉬운 곳"은 본 화면에 비춘 가설이고, 2단계 진단에서 확인한다.

### 4.1 여러 패턴에 걸쳐 되풀이된 것

| 관찰 | 어디서 |
|---|---|
| 고르기·확인·필터를 하단 시트로 한다. 시트 맨 아래 채움 버튼 하나 | 앱 예약·결제 3/3, 필터 3/3, 지도 2/3, 취소 2/3 |
| 필수 입력을 채우기 전에는 주 버튼을 비활성으로 둔다. 문구가 할 일을 말하기도 한다("모두 작성했어요") | 앱 글쓰기 3/3, 웹 생성하기 2/3, 웹 마이페이지 편집, 앱 생성하기 |
| 완료를 토스트 한 줄로 끝내지 않는다. 다시 확인할 곳·다음 일정·다음 행동을 대화상자나 시트로 알린다 | 앱 신청하기 3/3, 앱 생성하기 2/3, 글쓰기 토스트 0/3. 웹 설정 저장만 토스트 2/3 |
| 숫자는 하나를 크게 두고, 뜻을 문장으로 푼다("지난달보다 X원 늘었어요") | 앱 통계 3/3, 웹 내역 구역 구조, 웹 대시보드 비교 문구 2/3 |
| 지표 카드 4개 줄이 없다 | 웹 대시보드 0/3, 웹 통계 0/3 |
| 확인·상세는 라벨 왼쪽(회색)·값 오른쪽 행 | 앱 결제 확인 2/3, 앱 내역 2/2(금융), 웹 생성 상세, 웹 설정 폼 |
| 숫자·날짜는 기본 키보드·달력 격자가 아니라 앱이 그린 키패드, 휠, 드롭다운 3칸, 빠른 기간 칩 | 앱 결제 키패드 3/3, 필터 날짜 휠 2/3, 생일 드롭다운 3칸. 달력 격자는 웹 통계의 "직접 선택"뿐 |
| 데이터가 없으면 구역을 숨기지 않는다. 빈 문장 + 다음 행동, 0을 그대로, 견본이면 "가상의 데이터" 라벨 | 앱 통계 3/3, 웹 대시보드 3/3, 웹 통계·내역 |
| 색은 몇 자리에만. 행동마다 색이 다르면 확인 버튼·알림까지 그 색을 잇는다(매수 빨강·매도 파랑). 취소 버튼은 빨강이 아니다 | 앱 결제 2/3, 취소 빨강 0/3 |
| 이벤트 페이지는 예외로 색이 많다. 그림 안 글씨, 구역마다 다른 띠 | 앱 기획전 2/2(한 서비스) |

### 4.2 앱

**글쓰기** — 3흐름·27장(커뮤니티 3)
- 순서: 분류 → 제목 → 본문 → 사진 칸. 진입은 목록 위 떠 있는 버튼 2/3.
- 제목·본문은 테두리 없는 큰 안내 문구 입력 3/3(라벨 + 상자 0). 서식 툴바 0/3.
- 사진은 작은 정사각 칸 3/3, 개수 표시(0/10) 2/3. 제출은 하단 고정 폭 가득 2/3, 필수 전 비활성 3/3.
- 완료는 시트·경고창·상세 이동으로 갈렸고 토스트는 0.
- AI가 틀리기 쉬운 곳: 라벨 + 상자 폼, 서식 툴바·큰 끌어놓기 영역, 늘 활성인 제출, 토스트로 끝.

**필터** — 3흐름·17장(금융 1·커머스 2, 커머스는 한 서비스)
- 조건마다 칩 하나, 누르면 그 조건 하나만 든 하단 시트 2/3. 전체 화면 필터 0/3.
- 적용하면 칩 글자가 고른 값으로 바뀐다 2/3. 결과 수(191 → 38) 1/3. 정렬 시트는 고르는 즉시 반영.
- 날짜는 휠 피커 2/3, 빠른 기간 칩 1/3. 초기화는 글자 링크나 목록 머리.
- AI가 틀리기 쉬운 곳: 모든 조건을 한 패널에, 칩에 개수 배지만, 달력 격자, 초기화·적용을 같은 무게 버튼 둘로.

**예약·결제** — 3흐름·44장(금융 2·커머스 1, 날짜 예약 없음)
- 하단 고정 폭 가득 주 버튼 1개 3/3, 선택·확인·완료를 하단 시트로 3/3, 앱이 그린 숫자 키패드 3/3.
- 확인은 라벨-값 요약 시트에 회색 취소 + 채움 확인 2/3. 커머스 결제는 한 페이지 긴 스크롤을 회색 띠로 나누고 세부 선택은 시트로 한다.
- 수량 키패드 위에 10·20·50% 칩과 스테퍼를 한 줄로 둔다.
- AI가 틀리기 쉬운 곳: 매수·매도를 한 강조색으로, 기본 키보드·스테퍼 하나, 단계 마법사, 가운데 모달 확인.

**생성하기** — 3흐름·22장(커머스 2·뷰티 1)
- 선택지는 큰 타일 토글이고, 고르면 테두리와 글자만 강조색이다(면은 채우지 않는다). 다중 선택은 3열 격자 + "직접 작성".
- 생일은 연·월·일 드롭다운 3칸, 주소는 검색 한 칸 → 결과 → 지도 확인 → 상세주소 한 칸.
- 작은 생성(폴더)은 목록에 행을 바로 더하고 상단 "저장"으로 끝낸다. 가운데 완료 대화상자 2/3.
- AI가 틀리기 쉬운 곳: 라디오·셀렉트나 꽉 채운 선택, 달력, 시·구·동 여러 칸, 작은 생성에도 모달 폼 + 토스트.

**신청하기** — 3흐름·17장(커머스 2·뷰티 1)
- 하단 고정 신청 버튼 3/3. 원래 화면 위 대화상자·시트로 끝낸다 2/3.
- 본인 인증 칸은 하나씩 차례로 열리고 확인된 칸에 체크가 붙는다. 인증번호 칸에 남은 시간과 재발송.
- 완료 문구에 다시 확인할 곳·다음 일정 3/3. 완료 뒤 원래 버튼이 "신청 취소"로 바뀐다 1/3.
- AI가 틀리기 쉬운 곳: 칸을 한꺼번에, 별도 페이지, 토스트 한 줄, 절마다 카드.

**통계·리포트** — 3흐름·12장(금융 1곳)
- 긴 한 페이지: 라벨 → 큰 숫자 → 비교 문장(금액만 빨강) 3/3 → 해석 카드(출처 줄 → 굵은 결론 두 줄 → 근거 → 옅은 버튼, 가로 넘김) 3/3.
- 막대는 값을 직접 적고 축·범례·격자가 없다. 주·월·년 탭 없음. 하단 고정 버튼 0/3.
- AI가 틀리기 쉬운 곳: 숫자 타일 4개 + 선·도넛, 축·범례 차트, 증가를 초록으로, 빈 구역 숨김.

**내역** — 3흐름·8장(금융 2·커뮤니티 1)
- 요약(잔액·총액) → 목록 2/3. 라벨 왼쪽·값 오른쪽, 색은 핵심 값 하나 2/2(금융).
- 날짜 머리 묶음 0. 내용 단위(회차·게시판)로 묶고, 일부만 보인 뒤 더보기·조회›·아코디언.
- AI가 틀리기 쉬운 곳: 행마다 아이콘·색 배지·± 색, 열 머리 표, 모두 펼침, 기계적 날짜 묶음.

**지도뷰·내주변** — 3흐름·17장(금융·반려동물·적립)
- 지도 전체형 2/3(아래 "목록 보기" 알약이나 손잡이 시트 안 검색), 한 페이지형 1/3(지도 띠 1/4~1/3 + 정렬 칩 + 목록).
- 위치 버튼 3/3, 행마다 운영 상태 3/3, 거리 2/3, 하단 시트 체크 필터 2/3(결과 수가 든 버튼 "24개 병원보기"), 선택 핀 강조 2/3.
- 시트 높이: 핀 정보 약 30%, 필터 약 50%, 목록 약 80%. 색은 지도가 맡고 UI는 흰색.
- AI가 틀리기 쉬운 곳: 같은 빨간 핀, 50:50 고정 분할, 결과 수·초기화 없는 칩, 이름·주소만 있는 행.

**취소하기** — 3흐름·16장(반려동물 2곳)
- 사유 선택 필수 3/3, 선택지 5개 + 마지막 "기타" 3/3, 사유와 최종 확인을 한 창에 2/3.
- 다시 돌아올 길(장바구니 다시 담기·다시 예약) 3/3, 완료 뒤 목록에 취소 상태 2/3.
- 취소 버튼 빨강 0/3, 붙잡는 혜택 0/3, 체크 그림 완료 0/3.
- AI가 틀리기 쉬운 곳: 빨간 위험 버튼 + 경고 아이콘 대화상자, "떠나지 마세요" 혜택, 체크 그림 성공 화면, 환불 분해 생략.

**멤버십·요금제** — 3흐름·11장(금융 1·커머스 2, 모두 실적 등급)
- 맨 위 내 등급("○○님은 ○○ 고객입니다" + 단계 표시 + 다음 등급까지 한 줄) 2/3 → 낮은 등급부터 혜택 3/3 → 기준·갱신 시점 3/3.
- 혜택은 숫자(적립률·쿠폰 금액) 2/3. 열 비교표 0, 추천 배지 0, 하단 고정 버튼 0.
- AI가 틀리기 쉬운 곳: 3열 요금제 표 + 추천 + 월·연 토글, 하단 "업그레이드" 고정, 체크 목록, 기준 생략.

**기획전·이벤트** — 3흐름·23장(금융 1곳)
- 키 비주얼(3D 그림, 글씨도 그림 안) → 기간·대상·혜택 요약 카드 → 번호 혜택 구역(구역마다 다른 띠, 금액이 가장 큰 글자) → 긴 유의사항 → 심사필 번호.
- 하단 고정 버튼이 유의사항 직전에서 본문 자리에 멈춘다 2/2. 카운트다운 0(날짜 범위·D-n 배지).
- AI가 틀리기 쉬운 곳: 카운트다운·마감 임박, 그라데이션 히어로 + 작은 아이콘 카드, 유의사항 생략.

### 4.3 웹(로그인 뒤 도구가 대부분)

**대시보드** — 3흐름·8장(비즈니스툴 2곳)
- 왼쪽 사이드바(폭 15~20%), 큰 페이지 제목 없이 구역 이름이 하위 탭 줄에 작게.
- 지표는 3개 묶음(한 패널에 세로 구분선이나 세로 목록) 3/3, 따로 떨어진 카드 4개 줄 0/3. 지표 아래 비교 문구 2/3, 시계열은 선 그래프 2/3.
- 데이터가 없으면 첫 자리에 연동·시작 단계, 템플릿, "예시 데이터" 표시 3/3. 기간은 월 이동 ‹ › + 기간 세그먼트.
- AI가 틀리기 쉬운 곳: 그림자 카드 4개 + 막대 + 최근 표, 빈 첫 화면을 그럴듯한 숫자로, 그래프마다 카드·범례 반복, 날짜 범위 달력.

**통계·리포트** — 3흐름·14장(비즈니스툴 2·금융 1)
- KPI 숫자 타일 줄 0/3. 선 차트 2/3, 비교(기간 비교·전 주 점선) 2/3, 내보내기(표 .xlsx·리포트 PDF) 2/3.
- 기간 줄: 프리셋 글자 버튼(어제·오늘·이번 주·7일·30일 …) + 직접 선택(두 달 달력) + 단위 + 비교. 표는 총 개수·다운로드, 행 체크로 계열을 켜고 끈다.
- 색은 주 버튼·선택·계열 하나일 때의 선에만, 계열이 여럿일 때만 범주 색.
- AI가 틀리기 쉬운 곳: KPI 카드 4개 + 화살표, 기간 드롭다운 하나, 표·내보내기 없음, 표시 없는 가짜 숫자.

**생성하기** — 3흐름·20장(비즈니스툴 2곳)
- 지금 보던 화면 위 모달로 시작 3/3(전체 페이지 0). 처음에는 이름만 받고 나머지는 상세에서 2/3. 단계 마법사·실시간 미리보기 0/3.
- 조건 전 주 버튼 비활성 2/3, "(선택)" 표기 2/3, 저장과 시작을 나눔 2/3. 상세는 상태 단계 + 라벨-값 행 + 구역마다 오른쪽 테두리 버튼.
- AI가 틀리기 쉬운 곳: 진행 막대 마법사, 전체 페이지 폼, 저장 = 실행 한 버튼, 빠진 설정을 토스트로.

**내역** — 3흐름·11장(비즈니스툴 1곳, 현황 요약에 가깝다)
- 구역 = 작은 라벨 → 큰 숫자·D-day → 해석 문장 → 패널 → "+ … 보기". 표는 짧게 보이고 전체 보기로 넘긴다.
- 숫자 오른쪽·열 머리 ⓘ, 합계 행만 검정 면 + 계산식, 묶음 행 접기, 가로선만(줄무늬 없음). 페이지 번호·행마다 ⋯ 메뉴 없음.
- AI가 틀리기 쉬운 곳: 긴 표 + 페이지 번호 + 행마다 ⋯, 숫자만 나열, 합계 행 구분 없음, 빈 표 숨김.

**탐색** — 3흐름·16장(비즈니스툴 블로그 2·금융 시세 1)
- 폭 제한 가운데 정렬 3/3, 그림자 없음 3/3. 첫 항목을 크게(1 → 2열 → 3열) 2/3, 피드 중간 행동 띠 2/3, 번호 페이지 2/3.
- 글 카드는 표지 그림(약 1.9:1) + 분류 + 굵은 제목 두 줄 + 날짜, 테두리·배경 없음. 시세는 촘촘한 행.
- AI가 틀리기 쉬운 곳: 그림자 카드 + hover, 처음부터 같은 크기 격자, 무한 스크롤만.

**마이페이지** — 3흐름·10장(금융 2·비즈니스툴 1)
- 맨 위 작은 프로필 요약 3/3, 기록·활동은 숫자 카드가 아니라 메뉴 항목 3/3.
- 설정은 전용 사이드바 + "메인으로 돌아가기", 라벨 왼쪽·입력 오른쪽(입력 폭은 패널의 약 1/3), 저장·취소는 폼 아래 왼쪽 정렬, 저장 뒤 토스트 2/3.
- AI가 틀리기 쉬운 곳: 커버 그라데이션 + 숫자 카드 줄, 폭 가득 입력·폭 가득 저장, 늘 활성인 저장.

## 5. 웹 디자인 어워드 선정작 — 첫 화면 유형

최신 선정작 60개의 첫 화면(목록 썸네일)이다. 분야 분류에는 관공서·기업소개·쇼핑·패션·식품·건축·금융·교육·의료 등이 있고, 최신 60개는 브랜드·기업·에이전시 사이트가 대부분이다.

| 첫 화면 | 개수 |
|---|---|
| 사진·영상이 화면 가득(글은 그 위나 아래 한두 줄) | 21 (35%) |
| 큰 글자가 주인공(화면 폭을 채우는 영문·국문 글자) | 15 (25%) |
| 브랜드색 면·그래픽·3D 그림 | 15 (25%) |
| 흰 바탕 위 모델·제품 사진 | 3 (5%) |
| 어두운 바탕 + 짧은 문장 | 3 (5%) |
| 제품 화면·포털형 묶음 | 3 (5%) |

- 어두운 첫 화면이 약 19개(30%)다.
- suta의 랜딩 관례는 "히어로에 실제처럼 빽빽한 제품 화면"이다. 이 60개 중 그 형태는 3개뿐이다. 브랜드·기업 사이트는 사진·큰 글자·브랜드색 면으로 시작한다. suta에는 이 유형의 관례가 없다.

## 6. 지금 suta와 부딪히는 곳

**관례가 레퍼런스와 다르다**

| 지금 suta | 레퍼런스에서 본 것 | 근거 |
|---|---|---|
| 대시보드: 핵심 지표 3~4개, 흰 데이터 카드 | 지표 3개를 한 패널에 구분선으로 묶거나 세로 목록 + 큰 선 그래프. 카드 4개 줄 0/3. 데이터가 없으면 연동·시작 단계 | 4.3 대시보드·통계 |
| 랜딩: 히어로에 실제처럼 빽빽한 제품 화면 | SaaS 랜딩에는 맞다. 브랜드·기업 사이트 첫 화면은 사진·큰 글자·브랜드색 면 85% | 5절, 2026-10-14 설정·랜딩 조사 |
| 완료 알림: 정한 관례 없음(가장 가까운 것이 `toast-stack` 패턴) | 신청·생성 완료는 다음 할 일을 알리는 창, 토스트는 설정 저장 같은 작은 일에만 | 4.1 |
| 날짜 입력: 정한 관례 없음(`wheel-picker` 패턴만) | 휠·드롭다운 3칸·빠른 기간 칩이 먼저, 달력 격자는 범위 직접 선택에만 | 4.1 |

**suta 결과 화면에서 되풀이되는 것**(비교 이미지 속 suta 0.14·0.15 결과)

- 사진 대역이 한 가지 화풍이다. 숙소 대표 사진·프로필 격자·채팅 사진·피드 썸네일이 모두 납작한 도형 장면이고, 숙소가 진 이유가 "도형 플레이스홀더"였다.
- 강조색이 몇 가지로 모인다. 0.14의 8번 중 초록 4·거의 검정 2, 이커머스(0.8) 4번 중 짙은 초록 3, 0.15 이미지 첫 실행 8개 중 초록 3·벽돌·주황 3.
- 관례를 따른 결과가 다시 평균 템플릿이 된다(대시보드 카드 4개 + 막대 + 표, 랜딩 가운데 히어로 + 로고 띠 + 숫자 3개).
