| 항목 | 내용 |

## 1. 한눈에

- **suta 0.14는 앱 화면에서 졌다.** 앱 화면 요청 8개를 블라인드로 판정하니 4 : 12, 3 : 13이었다. 검사 수치는 깨끗했다(강조색 하나, 옅은 색 면 0, 이모지 0). 진 것은 사진 자리를 회색 칸으로 비우고, 요청한 사진 메시지를 빼먹고, 온보딩을 빈 카드로 그린 탓이었다.
- **잘 만든 앱은 색과 밀도를 콘텐츠가 맡는다.** 레퍼런스 앱 31곳의 화면 194장을 유형별로 다시 기록했다. 홈 34장 중 29장은 첫 화면의 10% 이상이 사진·그림이었고, 22장은 강조색 밖의 색(배너·분류 그림·로고)이 있었다. 시중 앱 16곳의 스토어 스크린샷에서도 12곳이 분류 바로가기·혜택 같은 큰 칸에 색이 든 그림 아이콘을 썼다. suta는 UI를 무채색으로 줄이면서 콘텐츠 자리까지 비웠다.
- **그림 아이콘은 큰 칸에만 맞았다.** 3차에서 은행 거래 행·알림 행까지 그림 아이콘으로 채웠더니 판정 16번이 모두 "이모지풍 아이콘이 제각각"이라며 졌다. 목록 행은 옅은 원 + 선 아이콘 한 가지로 되돌렸다.
- **페이지 점은 레퍼런스가 suta 편이었다.** 레퍼런스 7장의 점은 모두 지름 6\~9pt 원, 중심 간격 13\~18pt였고 알약형은 없었다. 일반 Claude는 3번 모두 알약형을 썼고 판정 모델은 그쪽을 골랐다. suta의 흠은 점을 44px 버튼으로 만들어 간격이 3배로 벌어진 것이었다.
- **5차까지는 15 : 17 안팎에서 움직이지 않았다.** 사용자가 "AS-IS와 TO-BE가 달라진 게 없어 보인다"고 했다. 다시 보니 채팅방 두 실행이 모두 렌더 결함(열 없는 grid 틀의 가로 넘침, 스크롤 칸 밖으로 샌 숨김 글자)이었고, 알림·은행·배달·온보딩은 판정이 짚은 세부(회색 아이콘만 있는 알림, 같은 아이콘의 거래 행, 아이콘 칸 같은 가게 사진, 형광색 그림)가 그대로였다.
- **최종(0.15.0, 6차)**: 판정 19 : 13, 20 : 12. 여섯 차례 중 처음으로 suta가 앞섰다. 채팅방 0 : 4 → 3 : 1(두 결함을 검사 규칙 두 개가 잡게 했다), 은행 1 : 3 → 2 : 2, 피드·배달 8번 모두 이겼다. 숙소(사진 대역이 "도형 플레이스홀더"로 읽힘)·온보딩(그림이 작음)·알림(모든 행을 칠함)은 여전히 졌다. 이모지 80 → 0, 접근성 위반 요소 232 → 17, 12px 미만 글자 97 → 0, 24px 미만 누르는 영역 17 → 0, 320px 넘침 1 → 0이다.

## 2. 방법과 한계

### 진단 — 앱 화면 요청 8개

- 지금까지의 벤치마크는 랜딩·대시보드·설정·로그인처럼 웹 화면이 많았다. 앱 화면만 모은 요청 8개(`evals/benchmark/app-prompts.json`)를 새로 만들었다.
  - 동네 커뮤니티 홈 피드, 배달 앱 홈, 숙소 상세, 중고거래 1:1 채팅방(사진 메시지 포함), 쇼핑 앱 알림(읽음 구분·날짜 묶음), 사진 SNS 내 프로필, 가계부 앱 온보딩 3장 + 알림 권한, 은행 앱 홈이다.
  - 결과는 390px 모바일 화면 하나로만 판정한다(`mobileOnly`). 판정 지시도 "실제 앱다운 배치"로 바꿨다.
- 요청마다 suta 없이 1번, suta 0.14.0 1번을 돌리고, 두 판정 모델이 순서를 바꿔 두 번씩 블라인드로 판정했다(32번).
- 벤치마크 스크립트 3개(`run.mjs`·`judge.mjs`·`report.mjs`)에 `--prompts`를 더해 다른 요청 세트를 돌릴 수 있게 했다.

### 레퍼런스 — 앱 31곳의 유형별 화면

- 처음 받은 디자인 레퍼런스 사이트의 앱 31곳에서, 서비스마다 화면 전체 목록(약 14,000장)을 다시 썼다. 8장마다 1장(1,687장)을 썸네일 시트로 만들어 에이전트 4개가 화면 유형을 붙였다.
- 유형마다 고르게 화면 359장을 골랐다. 알림·채팅방·프로필·은행 홈은 표본이 적어, 분류된 화면 앞뒤의 이웃 화면 1,362장을 시트 21장으로 더 훑어 23장을 더 골랐다.
- 이름을 가린 AI 화면 16장(진단의 suta 없이·suta 0.14)을 섞어, 에이전트 5개가 한 장씩 같은 형식으로 적었다. 형식은 머리 모양, 구역 순서, 사진·그림 몫, 면, 나누는 방법, 글자 단계, 강조색 자리, 강조색 밖의 색 수, 아이콘, 하단 탭·고정 버튼, 좌우 여백, 유형별 세부(채팅방의 말풍선 색·시간 자리, 알림의 안 읽음 표시 등)다.
- 받은 유형과 실제가 다른 화면은 빼고 셌다(382장 중 172장). 팝업·키보드가 덮은 화면, 운영체제 알림 센터, 앱 안 웹 페이지가 대부분이었다. 남은 레퍼런스는 194장(30곳)이다.

| 유형 | 장 | 서비스 |
|---|---|---|
| 홈 | 34 | 19 |
| 피드 | 20 | 11 |
| 상세 | 50 | 25 |
| 채팅방 | 19 | 6 |
| 알림 | 13 | 5 |
| 프로필 | 20 | 7 |
| 시작 안내 | 22 | 15 |
| 은행·자산 홈 | 16 | 4 |

### 한계

- 레퍼런스 사이트는 로그인 없이 31곳만 열린다. 사이트맵에 있는 나머지 61곳은 로그인이 필요해 쓰지 않았다. 시중 앱은 기기가 없어 직접 찍지 못했다. 그래서 채팅방·알림·은행 홈은 4~6곳뿐이고 값의 폭이 넓다.
- 캡처는 2023년 무렵 화면이다. 크기는 캡처 폭을 390pt로 환산해 눈으로 잰 값이다.
- 블라인드 판정 모델은 사진처럼 보이는 썸네일과 색 아이콘을 높게 친다. 진단에서 suta 없이 만든 피드의 썸네일은 그라데이션 + 이모지였는데 판정은 "실제 사진 썸네일"이라고 했다. 판정 숫자만으로 "AI 티"를 잴 수는 없다.
- 원자료(시트·기록 JSON·캡처)는 세션 임시 폴더에만 있다.

### 시중 앱 — 앱 마켓 스크린샷

- 레퍼런스에 사진 SNS·숙소·은행 앱 화면이 적어, 은행·배달·커머스·중고거래·숙소·SNS 분야에서 많이 쓰는 앱 16곳의 앱 마켓 상세 페이지(robots.txt가 허용한 경로)에서 스크린샷 121장을 받았다. 페이지 사이에 3초 쉬었다.
- 홍보용 캡처라 문구가 덮였고 화면 일부만 보인다. 값을 재지 않고, 어떤 자리에 무엇을 쓰는지(그림 아이콘·사진·카드)만 셌다.

## 3. 진단 — suta 0.14가 앱 화면에서 진 이유

판정은 두 모델 모두 suta 0.14의 열세였다(4 : 12, 3 : 13). 숙소 상세·프로필만 이겼다. 둘 다 suta 없이 만든 화면에 흠(하단 예약 바 없음, 탭 바 뒤로 시트 조각이 보임)이 있었다.

| 진 이유 | 판정에서 짚은 수(32번 중) | 요청 |
|---|---|---|
| 사진 자리가 회색 칸 + 아이콘(회색 자리표시) | 9 | 피드 4 · 배달 2 · 숙소 3 |
| 요청한 요소를 빼먹음 — 사진 메시지 | 4 | 채팅방 |
| 배너 글이 잘림, 바로가기가 글자 칩 한 줄 | 4 | 배달 |
| 회색 카드 안이 비어 덜 다듬어짐 | 4 | 온보딩 |
| 밋밋함 — 색 아이콘·대표 계좌 카드가 없다 | 4 | 은행 홈 |
| 안 읽음 구분이 약하고 아이콘이 들쭉날쭉 | 4 | 알림 |

- suta 0.14의 화면은 검사 수치가 깨끗했다. 강조색 하나, 옅은 색 면 0, 이모지 0이었다. 진 것은 색과 그림이 비어서였다.
- 레퍼런스와 견주면 원인이 보인다. 잘 만든 앱은 UI를 무채색에 가깝게 두지만, 색과 밀도를 사진·배너·분류 그림·로고가 맡는다(4절). suta는 "사진이 없으면 같은 비율의 옅은 바탕 칸"이라고 적어 두었고, AI는 그 칸을 회색 상자로 그렸다.

## 4. 레퍼런스

### 콘텐츠 그림

| 화면 | 첫 화면의 10% 이상이 사진·그림 | 강조색 밖의 색이 있다(사진 제외) |
|---|---|---|
| 홈 | 34장 중 29장 | 34장 중 22장 |
| 피드 | 20장 중 15장 | 20장 중 16장 |
| 상세 | 50장 중 30장 | 50장 중 23장 |
| 프로필 | 20장 중 15장 | 20장 중 10장 |
| 시작 안내 | 22장 중 15장 | 22장 중 6장 |
| 은행·자산 홈 | 16장 중 7장 | 16장 중 9장 |
| 채팅방·알림 | 32장 중 8장 | 32장 중 11장 |

- 강조색 밖의 색은 배너 바탕, 분류 그림(사진·3D 그림 아이콘), 은행·카드 로고, 국기 같은 콘텐츠 자리였다. 버튼·글자·탭의 색은 대부분 강조색 하나였다.
- 홈의 첫 화면 사진·그림 몫은 중앙값 30%, 시작 안내 25%, 프로필 20%다. AI 화면(진단 16장)은 suta 없이도 대부분 0~10%였다. 그 자리를 그라데이션 + 이모지로 채웠다.

### 채팅방(19장, 6곳)

- 머리는 뒤로 + 상대 이름이 18장이다. 하단 탭은 1장에만 있었다.
- 상대 말풍선은 회색 바탕 위 흰 면이 8장이다. 내 말풍선은 강조색 면(파랑 계열)이 가장 흔했다.
- 상대 원형 사진 12장, 시간은 말풍선 바깥 옆 12장, 읽음 표시 없음 15장(숫자 3장)이다.
- 입력칸은 회색 알약 12장, 위 선 + 상자 없음 6장이다. 날짜 구분 알약이 10장에 있었다.

### 알림(13장, 5곳)

- 종류 탭 7장(2칸이 흔하다, 선택 탭은 굵은 검정 + 밑줄). 시간은 본문 아래 11장이다.
- 안 읽음은 표시 없음 5장, 행 바탕 칠하기 4장(옅은 강조색·살구·옅은 회청), 점 2장이다.
- 행의 그림은 없음 5장, 원 그림 4장, 썸네일 3장이다. 행을 카드로 감싼 화면은 2장이다.

### 시작 안내(22장, 15곳)

- 상단 바 없음 18장, 가운데 정렬 15장, 건너뛰기 없음 17장, 하단 폭 가득 버튼 10장이다.
- 그림은 아이콘·그림 아이콘 6, 일러스트 5, 제품 화면 5, 사진 3이다. 제목 19~28(가운데 22), 글자 크기는 3단이다.

### 은행·자산 홈(16장, 4곳)

- 잔액 글자 중앙값 26. 대표 계좌는 큰 숫자 + 버튼 줄 7장, 흰 카드 5장, 행 4장이다.
- 계좌·거래 행의 왼쪽 원형 로고·그림 10장. 금액 오른쪽 9장, 왼쪽 7장이다.
- 옅은 회색 바탕 위 흰 카드(모서리 20 안팎)로 나눈 화면이 많다(카드 4 · 띠 4).

### 홈(34장, 19곳)

- 머리는 로고 왼쪽 10, 왼쪽 큰 제목 9. 머리 바로 아래는 탭 줄 11, 구역 제목 6, 배너 5다.
- 배너 25장, 가로 줄 28장, 하단 탭 5칸 17장. 글자는 20/14/12, 좌우 여백 20이다.

### 페이지 점(시작 안내·배너)

레퍼런스에서 점이 보이는 화면 7장을 원본 크기로 쟀다. 이번 실행들의 온보딩 점은 브라우저에서 쟀다.

| | 모양 | 지름 | 중심 간격 | 지금 장 |
|---|---|---|---|---|
| 레퍼런스 7장 | 원 | 6\~9pt | 12.6\~18pt | 같은 크기 원의 색(강조색·검정·흰색). 알약형 0장 |
| suta 없이(3번) | 원 + 알약 | 8 | 16 | 3번 모두 24×8 알약형, 폭(`width`)을 움직인다 |
| suta 0.15 1\~3차(6번) | 원 | 8 | 16(2번) · 44\~48(4번) | 색 |

- suta 쪽 4번은 점을 44×44 버튼으로 만들어 점 사이가 36~40px로 벌어졌다. 진입 스킬의 "누르는 영역 44px"를 점에도 적용한 결과다. 판정은 "점 간격이 지나치게 넓다"고 했다.
- `carousel` 정본 CSS는 점 버튼이 8×8이라 WCAG 2.5.8(24px)에 못 미쳤다. 데모 CSS만 24px 칸으로 고쳐져 있었다.

## 5. 반영

재측정 결과를 보며 여섯 차례 고쳤다(6절). 아래는 마지막 상태다.

- **콘텐츠 그림** `layout-principles/assets/content-art.css`
  - 요소 하나와 CSS만으로 그리는 사진 대역이다. 장면 14종(접시·그릇·식탁 위 접시·컵·실내·풍경·건물·병·상자·옷·가방·사람·동물·무늬)과 표시 2종(로고 `mark`·바로가기 칸 `tile`), 색 한 벌 7종이다.
  - 가게·메뉴처럼 종류로 갈리는 큰 사진 자리는 `dish`(식탁 위 흰 접시) + 그 메뉴의 그림 아이콘이다. 접시 장면만 반복하면 가게가 구분되지 않았고(3차), 옅은 `tile` 위 작은 그림은 "아이콘 타일이라 밋밋하다"로 읽혔다(5차).
  - 6차에서 접시·그릇 장면을 칸을 거의 채우도록 키웠다(짧은 변 기준 `closest-side`). 그릇은 동심원 대신 휘어지는 면 결과 달걀·파·고기 고명이다(전후 캡처 `docs/worklog/assets/2026-10-19-content-art-dish.jpg`).
- **그림 아이콘** `illustrations.ts`(57개)·`Illustration.tsx` — Microsoft Fluent Emoji Flat(MIT). 분류 바로가기·시작 안내·배너·가게 사진 대역 같은 큰 칸에만 쓴다. 목록 행과 틀은 선 아이콘이다. 달러 표시가 있는 돈주머니·지폐는 넣지 않았다.
- **검사** `layout-audit`
  - `.art` 선택자와 `--art-*` 변수의 색·그라데이션·반경·상자를 UI 규칙으로 세지 않는다(TDD, 테스트 4개).
  - 규칙 `stacked-icon-buttons`(error, TDD, 테스트 3개): `display: grid` 아이콘 버튼 둘 이상을 flex가 아닌 부모에 두면 세로로 쌓인다. 0.15 1차 은행 홈 2번이 모두 이 흠이었고, 규칙은 그 두 실행만 잡았다(다른 벤치마크 결과·스킬·데모 0건).
  - 규칙 `grid-blowout`(error, TDD): 행을 둘 이상 두고 하나를 `fr`로 채운 grid 틀에 열이 없으면, 입력칸 기본 폭이 틀을 화면보다 넓게 민다. 3\~5차 채팅방 3번이 390px에서 413\~458px로 넘쳤고, 벤치마크 산출물 383개에서 규칙은 그 3개만 잡았다.
  - 규칙 `hidden-text-escape`(error, TDD): 화면 높이 틀의 세로 스크롤 칸에 `position`이 없으면 그 안의 숨김 글자(`.sr-only`)가 칸 밖으로 새어 페이지가 길어진다. 2·5차 채팅방 3번이 이 흠으로 입력 줄 아래가 비었다(844px 화면의 페이지 높이가 942~1,429px). 처음 조건(숨김 글자 + 스크롤 칸)은 산출물 79개를 잡아 실제로 샌 것이 3개뿐이었다. 화면 높이 틀·세로 스크롤·칸 안의 숨김 글자로 좁혀 4개를 잡고 그중 3개가 실제로 샜다.
  - 빈 사진 자리를 잡는 규칙은 만들지 않았다. 진단 16장 중 8장이 사진 칸을 스크립트로 만들거나 채워, 마크업만으로는 구별할 수 없었다.
- **화면 관례** `screen-conventions.md`: 공통 `콘텐츠 그림`(그림 아이콘을 쓰는 자리·쓰지 않는 자리 포함)과 `페이지 점`, `채팅방`(화면 높이 가득·입력 줄 맨 아래·사진 메시지 크기), `알림`(점 + 굵은 본문, 안 읽은 알림 2~3개), `내 프로필`(회색 반폭 버튼 2개·하이라이트·아이콘 탭·3열 격자), `은행·자산 홈`(강조색 대표 계좌 카드·행은 선 아이콘), 홈·목록·시작 안내 추가 값.
  - 6차에서 더한 것: 채팅방 틀의 CSS(flex 세로, 대화 칸 `position: relative`, grid면 열 `minmax(0, 1fr)`). 알림 행은 상품을 가리키면 상품 사진, 아니면 종류마다 다른 선 아이콘, 모든 행에 본문 한 줄, 탭 점은 안 읽은 탭에만. 시작 안내 그림은 강조색 한 벌로 직접 그린 SVG 장면(그림 아이콘을 키우지 않는다), 위 줄에 앱 이름 + 건너뛰기, 제목 24\~28 두 줄. 은행 대표 계좌 카드의 버튼 짝(흰 면 + 흰 16% 면), 거래 행은 분류마다 다른 선 아이콘과 날짜 묶음, 은행마다 다른 색의 `art--mark`. 배달 홈 가게 카드는 사진 칸 120\~150(`art--dish`, 3장 묶음 가능), 배너는 진한 색 면 + 큰 그림. 숙소 상세의 순서와 썸네일 있는 객실 선택.
  - 근거는 5차 판정 이유와 시중 배달 앱 2곳의 스크린샷 16장(가게 카드 사진 3장 묶음, 원 없는 음식 사진 바로가기, 진한 색 혜택 배너)이다.
- **아이콘** `icons.ts`: 금융 거래 분류 8개(교통·카드·이체·장보기·통신·저축·입금·은행, Lucide 0.469.0)를 더해 64 → 72개.
- **톤** `tone.md`: 콘텐츠 그림의 색은 UI 색으로 세지 않는다. 큰 콘텐츠 칸은 그림 아이콘, 목록 행과 틀은 선 아이콘. 옅은 색 바탕은 선택 상태와 안 읽은 알림 행에만.

- **진입 스킬** `SKILL.md`: 절차 3·4단계, 금지선 2행, 값 표 `페이지 점`, 체크리스트 7항목(요청한 요소, 사진 자리, 시작 안내·은행 틀, 채팅방 틀 CSS, 아이콘 자리와 알림 행, 배달 가게 사진·숙소 객실, 넘침·링크 밑줄·예시 상태).
