# 색 조합·글꼴·문구 — 레퍼런스 재분석

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-10-14 |
| 계기 | 사용자 요청 — "처음에 줬던 레퍼런스 사이트들을 기준으로 색채 조합·폰트·문구도 개선해보자". 레퍼런스는 디자인 레퍼런스 사이트의 국내 앱 31곳 화면과 웹사이트 19곳이다(앞 조사와 같은 목록). 출처 이름은 남기지 않는다 |
| 반영 | suta 0.13.0 — `layout-principles`(무채색 토큰을 순수 회색으로, 글꼴 토큰 `--font-sans`, 색 조합 코어 `palette.ts`와 CLI `scripts/palette.mjs`, `tone.md` 강조색 맑기·무채색 온도·글꼴, 새 `copy.md`), `layout-audit`(규칙 5개: `muddy-accent`·`neutral-temperature`·`accent-contrast`·`meta-copy`·`mixed-tone`), 진입 스킬 절차·금지선(문구 표 신설)·값·체크리스트, 데모의 앱 문구 해요체, 패턴 문서 예시 문구 |

## 1. 한눈에

- **강조색이 탁하다.** 잘 만든 앱 31곳의 강조색은 맑았다(OKLCH 밝기 중앙값 0.67, 채도 0.18). suta를 설치한 Claude는 차분해 보이려고 짙은 청록·간장색·짙은 갈색을 골랐다 — 0.6~0.11 산출물의 강조색 19개 중 12개가 밝기 0.55 미만·채도 0.12 미만이었다. 잘 만든 앱은 31곳 중 1곳(브랜드색)뿐이다. 사용자가 "너무 검은색 위주"라고 한 인상이 이것이다.
- **무채색의 온도가 강조색과 따로 논다.** 잘 만든 앱의 글자색은 29곳 중 24곳이 순수 회색이었다. 기운 4곳은 모두 파랑 서비스의 파란 기운이다. suta 토큰(`#1b1e24` 등)은 푸른 회색이라, suta 산출물 26개 중 25개가 초록·갈색·빨강 강조색 옆에 푸른 회색 글자를 두었다.
- **글꼴을 고르지 않는다.** 잘 만든 웹사이트 19곳은 모두 자기 글꼴을 웹폰트로 불러왔다. AI 산출물 48개는 하나도 불러오지 않았다. suta 산출물은 `Pretendard` 이름까지 적었지만 파일이 없어 기기 기본 글꼴로 그려졌다.
- **문구는 말투 섞임과 개발용 문구가 문제다.** 잘 만든 앱의 오류·토스트·제목은 해요체가 76~87%다. 일반 Claude는 22번 중 11번 "(데모)"·"테스트 계정" 같은 개발용 문구를 화면에 남겼다(레퍼런스 7,539개 중 2개). 말투 섞임은 레퍼런스도 화면의 42%에서 틀렸다 — 따라 할 관례가 아니라 흔한 실수다.
- 버튼 문구의 꼴·길이, 느낌표·이모지 양은 AI와 레퍼런스가 비슷했다. 규칙을 만들지 않았다.
- **재측정(7절).** 같은 요청 6개를 0.12와 0.13으로 12번씩 돌렸다. 탁한 강조색 6 → 0, 푸른 회색 글자 10 → 0, 말투 섞인 실행 2 → 0이다. 블라인드 판정은 우열이 없었다(0.13 : 0.12 = 11:13·10:14). 판정 이유는 대부분 실행마다 갈리는 구성이었다.

## 2. 방법과 한계

### 자료

- **앱 화면의 색** — 앞선 색 실측(2026-10-08)에 쓴 31곳 1,116장(서비스마다 흐름 전체에서 고르게 36장)을 그대로 썼다.
  - 면: 같은 색이 가로 12px 이상 이어지는 픽셀만 센다. 사진·일러스트·글자는 거의 빠진다.
  - 강조색: 유채색 면(OKLCH 채도 0.07 이상, 밝기 0.35~0.92)을 색상각 30° 칸으로 묶어, 화면 수가 가장 많은 칸의 대표 색.
  - 글자색의 온도: 면을 뺀 어두운 무채 픽셀의 OKLab 중앙값(화면마다) → 서비스마다 그 중앙값. 처음에는 최빈값을 썼는데 압축 번짐과 검은 그림·키보드에 끌려가서 버렸다.
- **앱 화면의 문구** — 같은 1,116장을 에이전트 16개가 나눠 받아 적었다(서비스 둘씩).
  - 화면마다 서비스가 쓴 UI 문구를 역할(화면 제목·구역 제목·설명·라벨·입력 안내·도움말·채운 버튼·보조 버튼·탭·하단 탭·빈 상태·오류·토스트·대화상자 제목·본문·버튼·안내·홍보·OS)로 나눠 글자 그대로 옮겼다.
  - 사용자 콘텐츠(상품명·글·이름)와 데이터 값(가격·날짜)은 옮기지 않았다.
  - 제목 글꼴의 성격(평범한 고딕·디스플레이·둥근·명조·손글씨)을 함께 적었다.
  - 말투·길이·문장부호는 받아 적은 글자로 로컬에서 셌다.
- **웹사이트의 글꼴** — 앞 조사와 같은 19곳(robots.txt 허용). 390·1440px에서 보이는 글자 요소의 `font-family` 전체, 실제로 그려진 글꼴(크롬 개발자 도구 프로토콜의 `CSS.getPlatformFontsForNode`), 불러온 웹폰트(`document.fonts`)를 쟀다. 페이지 사이 3초 이상 쉬었다.
- **AI 산출물** — 앞선 벤치마크의 산출물 48개를 같은 지표로 쟀다. 일반 Claude 22개(퍼블리싱 16·증권 4·걷기 2)와 suta를 설치한 Claude 26개(0.6 16개, 0.9~0.11 10개)다. 색은 390 캡처, 글꼴·문구는 소스에서 쟀다.
- **디자인 피드백 사례(재독)** — 462편 분석 기록에서 글꼴·문구를 다룬 사례: 글꼴 규칙을 먼저 정한다, UI에 브랜드성 강한 글꼴을 깔지 않는다, 문구는 그 칸이 다루는 대상의 말로, 없어도 이해되는 설명은 뺀다, 칸에 들어갈 글자 수를 먼저 잰다.

### 한계

- 캡처가 손실 압축(webp)이라 글자색의 밝기 절댓값은 번짐 때문에 높게 나온다. 온도(채도·색상각)만 판단에 썼다.
- 옅은 면의 온도는 판단에 쓰지 않았다. iOS 키보드의 푸른 회색(`#d4d8de`)이 면으로 잡혔다.
- 앱 캡처로는 글꼴 이름을 알 수 없다. 제목이 본문과 다른 글꼴인지만 봤다.
- 문구 받아 적기는 에이전트의 판독이다. 글자가 작거나 가려진 화면은 `partial`로 표시했다(약관·잘린 목록).
- AI 산출물은 앞선 벤치마크의 것이라 요청문이 서로 다르다(퍼블리싱 8종·증권·걷기). 재측정(7절)은 같은 요청문으로 따로 돌렸다.
- 원자료(캡처·받아 적은 문구·측정 JSON)는 세션 임시 폴더에만 두었다.

## 7. 재측정 — 같은 요청, suta 0.12 → 0.13

### 방법

- 퍼블리싱 벤치마크의 요청 6개(로그인·메뉴 상세·검색 결과·설정·옵션 시트·랜딩)를 suta 0.12와 0.13으로 두 번씩 돌렸다(조건마다 12번). 0.12는 main의 플러그인을 작업 트리로 따로 꺼내 실었다.
- 0.13 첫 재측정에서 랜딩 두 번이 axe 대비 위반(4.49·4.4:1)을 냈다. palette가 반올림한 대비로 판정한 탓이라 고친 뒤(반올림 없이, 4.6 목표) 0.13을 다시 12번 돌렸다. 아래는 다시 돌린 결과다.
- 측정은 앞 절과 같다. 강조색은 소스의 `--color-accent`, 글자색 온도는 390 캡처, 글꼴·말투는 소스, axe는 390 렌더에서 쟀다. 검사 경고는 두 조건 모두 현재 검사기로 다시 셌다.
- 블라인드 판정: 0.12와 0.13의 같은 번호 실행을 짝지어(1↔1, 2↔2) 이름 없이 보여 주고 고르게 했다. 짝마다 순서를 바꿔 두 번, 판정 모델 둘(기본 모델과 다른 모델)이다. 판정 기준에는 색·글꼴·문구를 따로 넣지 않았다(위계·읽기 쉬움·간격·배치·완성도).

- **색.** 탁한 강조색이 없어졌다. 카페 메뉴·옵션 시트는 갈색·숲색 대신 주황(`#c65013`·`#cb4b00`)을, 랜딩은 짙은 청록 대신 초록(`#00864b`)을 골랐다. 모두 palette가 낸 값(흰 글자 4.5:1에 맞춰 같은 색상각으로 어둡게 한 값)이다. 초록은 흰 글자에 맞추느라 밝기 0.54\~0.55·채도 0.12\~0.14로, 탁한 색 경계 바로 위다. 로그인·설정은 0.12처럼 거의 검정 주 버튼이다(근거가 없으면 거의 검정, tone.md 1절).
- **무채색.** 12번 모두 순수 회색 토큰을 그대로 썼다.
- **문구.** 0.12의 "모으세요 / 받습니다", "~하시겠습니까" 같은 섞임이 없어졌다. 개발용 문구는 두 조건 모두 없었다.
- **글꼴.** 12번 모두 `--font-sans`를 썼지만 벤치마크는 외부 파일을 막아 파일은 불러오지 못했다. 실제 프로젝트에서 `npm i pretendard`가 지켜지는지는 이 측정으로 확인하지 못했다.

### axe 위반과 검사 경고

- **선택 바탕 위 강조 글자(랜딩 2번째, 4.47:1).** palette가 강조 글자를 흰 면·옅은 바탕에서만 맞추고, 자기가 낸 선택 바탕(강조색 10%)은 보지 않았다. 같은 짝이 옵션 시트 두 번·검색 결과 한 번에도 있었다(4.45~4.49:1, 렌더에서는 그 짝이 쓰이지 않아 axe에 안 잡혔다). `accent-contrast`가 넷을 모두 잡았다. 재측정 뒤 palette가 선택 바탕에서도 맞추게 고쳤다(테스트 추가, 재측정 안 함).
- **네이버 초록 버튼의 흰 글자(로그인 2번째, 2.25:1).** 화면 관례는 "네이버는 흰 바탕 + 로고"인데 따르지 않았다. 관례에 대비 수치를 덧붙였다(재측정 안 함).
- **`tinted-surface`가 palette의 선택 바탕 변수와 카카오 노랑 버튼을 잡았다.** 문서가 허용한 자리(선택 상태 하나에 옅은 강조색)를 검사가 막고 있었다. 선택 바탕 변수는 세지 않게, 채도 0.13 이상의 채운 색은 옅은 면이 아니게 고쳤다(TDD). 0.12의 로그인도 같은 오탐이 있었다.
- 옵션 시트의 `nested-card` 경고(0.12 11·6개, 0.13 15·12개)는 시트 안 칩·라디오를 상자 안 상자로 센 것이다. 이번 범위 밖이라 그대로 두었다. 렌더에서 잰 중첩 상자는 0.12 6개, 0.13 1개다.

### 블라인드 판정

| 요청 | 0.13 : 0.12(기본 모델) | 0.13 : 0.12(다른 모델) | 판정 이유 |
|---|---|---|---|
| 랜딩 | 2 : 2 | 2 : 2 | 1번째는 0.13(일정 카드가 겹침 경고로 가치를 보여 줌), 2번째는 0.12(0.13 제목 마지막 줄에 "모아요"만 남음) |
| 로그인 | 1 : 3 | 0 : 4 | 0.13 데스크톱이 흰 띠가 화면 끝까지 늘어난 배치, 링크가 흐림, 네이버 아이콘 크기·초록 버튼 대비 |
| 메뉴 상세 | 2 : 2 | 2 : 2 | 0.13 옵션 행 간격·주황 주 버튼이 선명함 ↔ 0.12 "카페에 어울리는 갈색", 0.13 "주황이 튐"·메뉴명이 작음 |
| 옵션 시트 | 0 : 4 | 0 : 4 | 0.13 1번째는 상품 사진 자리가 빈 회색, 2번째는 첫 화면에 시트·토스트가 열려 있지 않음 |
| 검색 결과 | 4 : 0 | 4 : 0 | 거리 오른쪽 정렬·검색어 강조·영업 시간, 실제 사진 |
| 설정 | 2 : 2 | 2 : 2 | 1번째는 0.12(구역 제목·뒤로 가기), 2번째는 0.13 |

- 두 모델 모두 0.13을 더 낫다고 보지 않았다(11:13, 10:14). 판정 이유 48개 중 색을 말한 것은 7개, 글꼴·문구 쪽은 한 단어만 남는 줄바꿈 5개(0.13 랜딩 4, 0.12 메뉴 설명 1)뿐이다. 나머지는 실행마다 갈리는 구성(빈 사진 자리, 첫 화면에 시트를 열어 두었는지, 설정의 구역 제목)이다. 이번 개선이 겨냥한 색·글꼴·문구는 이 판정 기준으로는 우열이 드러나지 않았다.
- 색을 말한 7개 중 5개는 0.12의 짙은 갈색·숲색을 "카페 분위기에 맞는다·차분하다", 0.13의 주황을 "튄다"고 봤다(그중 3개가 0.12를 골랐다). 주황을 "선명하다"고 본 것이 1개, 네이버 초록 버튼의 대비를 짚은 것이 1개다. 레퍼런스의 커피 서비스는 초록·노랑이었고 탁한 강조색은 31곳 중 1곳뿐이라 규칙은 바꾸지 않았다. 업종 분위기는 사진·그림이 맡고 강조색은 맑게 둔다(tone.md 3절). 다만 판정 모델의 취향이 차분한 짙은 색 쪽이었다는 것은 기록해 둔다.
- 제목 마지막 줄에 한 단어만 남는 흠(0.13 랜딩, 0.12 메뉴 설명)은 suta 어디에도 안내가 없었다. 제목 `text-wrap: balance`, 설명 문단 `text-wrap: pretty`를 tone.md 5절과 SKILL.md에 더했다(재측정 안 함).
