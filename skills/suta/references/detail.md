# 디테일 — 요청한 것을 끝까지 만든다

뼈대가 맞아도 화면이 덜 만든 것으로 읽힐 때가 있다. 재측정에서 suta가 진 판정이 든 이유는 색이나 간격이 아니었다. "단조롭고 입력이 번거롭다"(모임 만들기, 진 판정 10번 모두), "평평한 목록이라 밀도와 완성도가 한 단계 낮다"(숙소 객실 목록), "구성이 빈약하다"(앨범 리뷰), "메뉴가 하나뿐이다"(여행 기사, 진 판정 12번 중 7번)였다.

요청에 없는 기능·구역을 더해서 채우지 않는다(`SKILL.md` "요청 범위와 사실 정보"). 요청한 요소 하나하나를 끝까지 만든다. 이 문서는 그 깊이의 기준이다. 경로는 스킬 폴더 기준이다.

## 쓰는 범위

- 프로젝트에 컴포넌트가 있으면 그 컴포넌트의 상태와 모양을 쓴다. 4절의 "기본 모습"은 기준이 없을 때의 값이다.
- 4절의 포커스·오류·잠금, 5절의 누르는 영역·넘침은 사용 문제다. 기존 컴포넌트에서도 빠져 있으면 고친다(`SKILL.md` "늘 지키는 선").
- 이 문서는 새 화면·구역·데이터 항목을 더하는 근거가 아니다.

## 1. 요소마다 다섯 가지를 묻는다

요청한 요소를 하나씩 놓고 위에서부터 묻는다. 얕은 화면은 대개 첫 줄에서 멈춘 화면이다.

| 묻는 것 | 얕게 만든 것 | 끝까지 만든 것 | 절 |
|---|---|---|---|
| 내용이 실제 같은가 | 같은 길이 이름 3개, 모두 10,000원 | 길이와 상태가 섞인 6개 이상, 끝자리까지 있는 값 | 2 |
| 값의 종류에 맞는 조작인가 | 항목마다 같은 빈 입력칸 | 고르는 값은 고르게, 기본값이 든 채로 | 3 |
| 상태가 다 있는가 | 기본 모습 하나 | 눌림·포커스·선택·잠김·진행·오류 | 4 |
| 값을 읽는 데 필요한 것이 옆에 있는가 | 숫자만 | 단위, 기준 시각, 전체 중 몇 개, 남은 양 | 5 |
| 누르면 끝까지 이어지는가 | 눌러도 화면이 그대로다 | 엮인 값이 함께 바뀌고 결과를 알린다 | 6 |

예: 요청의 "인원 선택".

- 얕게: 라벨 "인원" + 빈 숫자 칸.
- 끝까지: 기본값 2명이 든 스테퍼(`patterns/quantity-stepper`). 1명에서 빼기가 잠기고 최대에서 더하기가 잠긴다. 옆에 "최대 8명" 한 줄이 있다. 인원을 바꾸면 하단 바의 금액이 함께 바뀐다.

## 2. 내용 — 견본 데이터를 설계한다

견본 데이터는 화면의 일부다. 데이터가 단조로우면 구성이 맞아도 시안으로 읽힌다. 데이터는 한 곳에 모으고(`SKILL.md` "사실 정보"), 화면의 숫자는 그 데이터에서 계산한다.

| 무엇 | 기준 |
|---|---|
| 개수 | 목록은 첫 화면을 넘겨 스크롤된다(행 6개 이상, 격자 6칸 이상). 세 개짜리 목록에서는 반복 단위의 규격이 보이지 않는다 |
| 길이 | 가장 짧은 값, 보통 값, 두 줄로 꺾이는 가장 긴 값을 하나씩 넣는다 |
| 상태 | 한 가지 상태만 두지 않는다. 품절 하나, 할인 일부, 안 읽은 알림은 맨 위 2~3개, 스위치는 켜짐과 꺼짐 |
| 숫자 | 실제 값의 꼴이다. 8,500원·12,000원·13,900원처럼 끝자리가 다르다. 평점은 4.3·4.8처럼 고르지 않다. 합계·비율은 낱개에서 계산한다 |
| 시각 | 가까운 것은 상대 시각(방금·3분 전·어제), 먼 것은 날짜(11월 3일). 한 목록에서 새것이 위다 |
| 날짜 | 오늘을 기준으로 계산한다. 코드에 적어 둔 지난 날짜가 "예약 가능"으로 보이지 않게 한다 |
| 이름 | 사람·가게·상품 이름이 서로 다른 꼴이다. 실존 인물·회사 이름은 쓰지 않는다 |
| 사진 자리 | 회색 칸으로 비우지 않는다. 내용에 맞는 콘텐츠 그림을 둔다(`patterns/layout-principles/assets/content-art.css`) |

## 3. 조작 — 값의 종류로 고른다

모든 항목을 같은 텍스트 칸이나 드롭다운으로 두지 않는다. 값의 종류가 조작을 정한다. 프로젝트에 그 컴포넌트가 있으면 그것을 쓴다.

| 값의 종류 | 조작 | 패턴 |
|---|---|---|
| 켜짐·꺼짐, 누르면 바로 적용 | 스위치 | `switch` |
| 2~3개 중 하나, 흔한 기본값이 있다 | 세그먼트. 늘 한 칸이 골라져 있다 | `segmented-control` |
| 2~3개 중 하나, 기본값을 정할 수 없다 | 테두리 칩 줄이나 라디오 | `checkbox-radio` |
| 4~8개 중 하나나 여럿 | 칩. 화면 끝에서 잘리지 않게 줄을 감싼다 | — |
| 8개를 넘는 목록에서 하나 | "라벨 + 현재 값 + 꺾쇠" 행 → 하단 시트(휴대폰), 셀렉트(데스크톱) | `bottom-sheet`, `select` |
| 범위가 작은 수(인원·수량) | 흔한 기본값이 든 스테퍼 | `quantity-stepper` |
| 범위가 있는 값(가격대·거리) | 슬라이더 + 지금 값 글자 | `range-slider` |
| 가까운 날짜(2주 안) | 가로로 넘기는 날짜 줄(요일 + 날짜, 오늘 표시) | — |
| 먼 날짜·시각 | 행을 누르면 시트의 달력이나 휠. 기기 기본 날짜 칸을 그대로 두지 않는다 | `wheel-picker` |
| 정해진 시간대(예약) | 시간 칩 격자. 마감은 흐린 글자 + 잠김 | — |
| 사진 | 작은 정사각 칸 줄. 첫 칸은 추가 + "0/10" | `file-upload` |
| 인증번호 | 자리마다 칸. 붙여넣기와 문자 자동 입력을 받는다 | `otp-input` |
| 짧은 글 | 한 줄 입력칸 + 맞는 `inputmode`·`autocomplete` | `floating-label` |
| 긴 글 | 5~6줄에서 시작해 글에 따라 늘어나는 칸 + 글자 수 | — |

- 고르는 조작에는 가장 흔한 답을 기본값으로 둔다. 빈 스테퍼·아무것도 고르지 않은 세그먼트는 비활성처럼 보인다.
- 한 화면에 같은 종류의 값은 같은 조작이다. 같은 줄의 고르는 칸은 높이와 라벨 간격을 맞춘다.
- 작성 폼의 칸 모양·라벨·필수 표시는 `patterns/layout-principles/references/screen-conventions.md`의 "글쓰기·작성"에 있다.

## 4. 상태 — 컴포넌트마다 한 벌

화면에 컴포넌트를 두면 그 컴포넌트의 상호작용 상태가 CSS에 있어야 한다. 요청에 없는 상태 화면을 더 만들라는 뜻이 아니다. 버튼이 있으면 그 버튼의 눌림·포커스·잠김이 있어야 한다는 뜻이다.

| 상태 | 언제 | 기본 모습(기준이 없을 때) | 놓치기 쉬운 것 |
|---|---|---|---|
| 호버 | 마우스가 올라왔다 | 면의 톤이 한 단계 바뀐다. 위치·크기·그림자는 그대로다 | `@media (hover: hover)` 안에 둔다. 밖에 두면 터치 뒤에 호버가 남는다 |
| 눌림 | 누르고 있다 | 살짝 줄거나 어두워진다. 누를 때 60ms, 돌아올 때 220ms | `-webkit-tap-highlight-color`를 끄면 대신할 눌림이 있어야 한다(`patterns/press-feedback`) |
| 포커스 | 키보드로 닿았다 | `outline: 2px solid` + `outline-offset: 2px`. 바탕과 3:1 이상 | `:focus-visible`에 둔다. `overflow: hidden`인 부모가 링을 자르면 offset을 음수로 둔다 |
| 선택 | 골랐다·켰다·지금 탭이다 | 강조색의 약한 표현 + 모양 하나(체크·굵은 글자·밑줄) | 색만 바꾸지 않는다. `aria-selected`·`aria-checked`·`aria-current`·`aria-pressed` 중 맞는 것을 단다 |
| 잠김 | 지금은 누를 수 없다 | 같은 자리·같은 크기, 옅은 면과 옅은 글자 | 왜 잠겼는지가 근처에 보인다(버튼 위 한 줄). 화면에서 사라지게 하지 않는다 |
| 진행 | 눌러서 처리 중이다 | 버튼 폭은 그대로, 글자 자리에 진행 표시. 다시 눌리지 않는다 | `aria-busy`. 끝나면 결과를 알린다(`patterns/loading-button`) |
| 오류 | 값이 틀렸다 | 그 칸 아래 한 줄(오류 색) + 칸 테두리 | `aria-invalid` + `aria-describedby`. 값을 고치기 시작하면 오류가 풀린다 |
| 빈 값 | 아직 내용이 없다 | 상황 + 할 일 + 행동 하나 | 제목·탭·조건은 그대로 남는다 |
| 불러오는 중 | 내용을 기다린다 | 내용과 같은 자리·크기의 뼈대 | 200ms 안에 오는 응답에는 띄우지 않는다(`patterns/skeleton`) |

컴포넌트마다 필요한 상태는 다음과 같다.

| 컴포넌트 | 있어야 하는 상태 |
|---|---|
| 버튼 | 호버·눌림·포커스·잠김. 제출 버튼은 진행 |
| 입력칸 | 포커스·채워짐·오류·잠김 |
| 목록 행·카드(누를 수 있는) | 호버·눌림·포커스. 고르는 목록이면 선택 |
| 칩·세그먼트·탭 | 호버·눌림·포커스·선택. 마감된 선택지는 잠김 |
| 스위치·체크·라디오 | 포커스·선택·잠김 |
| 목록·피드 영역 | 불러오는 중·빈 값·오류(다시 시도) |

상태가 바뀌어도 크기는 그대로다. 색·테두리·`transform`만 바뀐다. 상태에 따라 높이가 바뀌면 아래 내용이 밀린다.

## 5. 마감 — 가까이서 보이는 것

값 하나하나는 작지만 모이면 손으로 만든 화면과 아닌 화면을 가른다.

| 자리 | 마감 |
|---|---|
| 값 옆의 맥락 | 숫자에는 단위가 붙는다. 바뀌는 값에는 기준이 있다(오늘 09:00 기준, 지난주 대비). 목록에는 전체 개수가, 한도가 있는 것에는 남은 양이 있다(2/10, 남은 자리 3). 요청한 값을 읽는 데 필요한 것이라 요청 범위 안이다 |
| 세로로 나란한 숫자 | `font-variant-numeric: tabular-nums` + 오른쪽 정렬. 바뀌는 숫자(타이머·금액)도 같다 |
| 제목과 문단 | 제목 `text-wrap: balance`, 문단 `text-wrap: pretty`, 한국어 `word-break: keep-all` |
| 긴 값 | 한 줄 말줄임인지 두 줄에서 자를지(`-webkit-line-clamp`) 요소마다 정한다. flex 자식에 `min-width: 0` |
| 아이콘과 글자 | 한 줄에 놓이면 `align-items: center`, 간격 4~8. 아이콘은 한 벌이다 |
| 구분선 | 글자가 시작하는 선에 맞춰 들여쓴다(아바타가 있는 행은 글자 열부터). 마지막 행 뒤에는 선이 없다 |
| 누르는 영역 | 보이는 크기가 작아도 영역은 44px이다. 안쪽 여백이나 `::after`로 넓힌다 |
| 스크롤의 끝 | 하단 고정 바 높이 + `env(safe-area-inset-bottom)`만큼 아래 여백. 시트·모달 안은 `overscroll-behavior: contain` |
| 가로로 넘기는 줄 | 첫 항목이 본문의 왼쪽 선에 맞는다. `scroll-snap`이 있고 스크롤바는 숨긴다. 오른쪽 끝에서 다음 항목이 잘려 보인다 |
| 고정 머리 아래의 닻 | `scroll-margin-top`을 머리 높이만큼 둔다. 머리가 제목을 가리지 않는다 |
| 터치 | `touch-action: manipulation`으로 두 번 누르기 확대의 지연을 없앤다. 버튼 글자는 `user-select: none` |
| 이미지 | `aspect-ratio`로 자리를 먼저 잡는다. 불러오는 동안 옅은 바탕색이 보인다. 화면 밖 이미지는 `loading="lazy"`. `alt`가 있다 |
| 입력칸 | 값에 맞는 `type`·`inputmode`·`autocomplete`·`enterkeyhint`. 금액은 자릿수를 끊어 보인다. Enter로 제출된다 |
| 제출 뒤 오류 | 첫 오류 칸으로 포커스가 간다. 화면이 그 칸까지 스크롤된다 |
| 문서 | `<html lang="ko">`, 화면마다 다른 `<title>`. 제목 요소(`h1`~`h3`)의 순서가 화면의 위계와 같다 |

## 6. 반응 — 요청한 행동은 끝까지 간다

- 누를 수 있는 것은 누르면 화면의 무언가가 바뀐다. 담으면 개수 배지가, 필터를 적용하면 칩 글자와 결과 수가, 제출하면 진행 표시와 결과 알림이 바뀐다. 눌러도 그대로인 버튼은 덜 만든 화면으로 읽힌다.
- 엮인 값은 함께 바뀐다. 수량을 바꾸면 합계와 버튼의 금액이, 조건을 바꾸면 결과 수와 목록이 바뀐다. 한 곳만 바뀌면 화면의 숫자가 서로 맞지 않는다.
- 요청에 없는 다음 화면은 만들지 않는다. 그 버튼에는 눌린 반응과 결과 알림까지만 둔다. 링크 자리(메뉴·더 보기)는 `href="#"` 대신 버튼이나 실제 자리 주소로 두고, 보고에 연결할 곳으로 적는다.
- 되돌릴 수 없는 행동(삭제·결제)은 누르기 전에 한 번 묻는다. 묻는 대화상자의 버튼은 "취소" + 행동 이름이다.
- 결과 알림은 스크린 리더에도 전달된다(`role="status"`). 알림은 사건만 읽는다.

## 7. 빈약해 보일 때 — 더하지 않고 깊게 한다

화면이 비어 보이면 구역을 더하기 전에 아래 순서로 본다. 왼쪽은 재측정의 판정이 실제로 든 말이다.

| 증상 | 흔한 원인 | 범위 안에서 고치는 법 |
|---|---|---|
| "단조롭다, 입력이 번거롭다" | 항목마다 같은 빈 입력칸·드롭다운 | 3절. 값의 종류로 조작을 바꾸고 기본값을 넣는다 |
| "평평한 목록이다, 밀도가 낮다" | 행이 글자 한 줄뿐이다 | 행을 "그림 + 이름·조건 + 오른쪽 값"으로 짠다. 그림은 그 행의 내용을 그린 것이다 |
| "구성이 빈약하다" | 요청한 것을 글자 한 줄씩으로만 뒀다 | 요청한 값을 보이는 방식을 갖춘다(평점은 숫자 + 막대, 상태는 배지, 본문은 소제목·인용). 5절의 맥락을 붙인다 |
| "시안 같다, 비어 보인다" | 사진 자리가 회색 칸이고 큰 칸까지 무채색 선 아이콘이다 | 콘텐츠 그림과 그림 아이콘(`references/defaults.md` 4절) |
| "덜 만든 화면이다" | 나가는 길·제목·사이트 머리가 없거나 메뉴가 하나다 | 화면의 틀을 갖춘다(`SKILL.md` "요청 범위와 사실 정보") |
| "밋밋하다, 위계가 약하다" | 모든 글자가 같은 크기·굵기다 | `references/design.md` 3절의 세 층. 결정은 본문의 1.5배 이상 |
| "평평하다, 어디가 위인지 모르겠다" | 떠 있는 것과 놓인 것이 같은 면이다 | `patterns/layout-principles/references/elevation.md` |
| "어느 화면이나 같아 보인다" | 유형과 상관없이 같은 틀이다 | `references/design.md` 2절의 일에서 뼈대를 다시 잡는다 |

그래도 비어 보이면 더할 만한 것을 보고에 제안으로 적는다. 판정이 고를 만한 것(찜·공유·후기)을 앞에 적는다.

## 8. 확인

- [ ] 요청한 요소마다 1절의 다섯 가지를 물었다.
- [ ] 목록의 견본 데이터가 6개 이상이고 길이·상태·숫자의 끝자리가 섞였다. 합계는 데이터에서 계산된다.
- [ ] 고르는 값은 값의 종류에 맞는 조작이고 기본값이 들어 있다.
- [ ] 누를 수 있는 것마다 호버(정밀 포인터에서만)·눌림·포커스가 있고, 잠긴 것은 이유가 보인다.
- [ ] 숫자에 단위와 기준이 붙어 있고, 세로로 나란한 숫자는 `tabular-nums`다.
- [ ] 누를 수 있는 것은 누르면 화면이 바뀌고, 엮인 값이 함께 바뀐다.
- [ ] 상태가 바뀌어도 요소의 크기가 그대로다.
