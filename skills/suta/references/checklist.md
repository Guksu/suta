# 마무리 확인 — 기준이 없을 때와 화면 유형별

`SKILL.md`의 "끝내기 전에"(요청 대조·사용 문제·사실 정보)를 먼저 확인한 뒤, 해당하는 절만 확인한다. 경로는 스킬 폴더 기준이다.

## 디자인 기준이 없을 때

프로젝트에 디자인 기준이 있으면 이 절은 건너뛴다. 그 체계를 따른 결과라면 아래와 달라도 고치지 않는다(`references/defaults.md`).

- [ ] 1순위 요소가 하나다 — 가장 큰 글자 하나, 채운 주 버튼 하나. 보조 버튼은 글자·아이콘이다.
- [ ] 같은 정보·같은 행동이 한 곳에만 있다. 위에 고정된 줄은 한 줄이다.
- [ ] UI의 유채색이 강조색 + 오류 빨강을 넘지 않고(시세 화면의 등락 색 짝, 보상 그림의 금·은·동은 따로), 옅은 색 면(연노랑·살구·연민트)과 색 알약·색 아바타가 없다.
- [ ] 사진 자리가 비어 있지 않다 — 실제 사진이나 내용에 맞는 콘텐츠 그림이고, 회색 칸·사진 아이콘·이모지가 없다. 배너 글이 360px에서 잘리지 않는다.
- [ ] 아이콘은 한 벌(같은 크기·선 굵기)이고 이모지가 없다.
- [ ] 상자 안에 상자가 없고, 묶음은 간격(묶음 안 ≤ 묶음 사이의 1/2)으로 보인다.
- [ ] 강조색을 정했고(이유 한 줄, 근거 없는 기본 파랑이 아니다), 채운 면은 주 행동 하나, 같은 색이 선택 상태·링크에 이어진다.
- [ ] 강조색이 맑고(탁한 색·옅은 파스텔이 아니다) 주 버튼 위 글자가 4.5:1 이상이다. 무채색이 순수 회색이거나 강조색 쪽으로만 기울었다.
- [ ] 글꼴을 파일로 불러왔다(`--font-sans`). 제목용 글꼴은 짧은 제목에만 있다.
- [ ] 본문 크기·큰 글자의 굵기와 자간·명조와 고정폭을 쓰는 자리가 업종과 읽는 조건에 맞다(공공·긴 글 17~19, 빽빽한 목록 14, 명조는 매체·브랜드의 몇 자리, 고정폭은 코드만).
- [ ] 면이 두 단계다(흰 면 + 옅은 바탕). 카드에 테두리와 그림자를 함께 쓰지 않았다.
- [ ] 가장 많은 글자가 본문 크기이고, 글자 색은 세 단계 안에서만 골랐다.
- [ ] 간격·글자 크기·반경은 토큰(척도)에서만 골랐다. 업종에 따라 본문 크기를 바꿨다면 토큰의 값을 바꿨다.
- [ ] 링크로 감싼 카드·목록 행에 기본 파란 밑줄이 남지 않았다(`color: inherit; text-decoration: none`). 예시 데이터는 상태가 섞였다 — 안 읽은 알림은 맨 위 2~3개, 스위치는 켜짐·꺼짐.
- [ ] 말투가 해요체 하나이고(약관만 합쇼체), 같은 행동은 같은 이름이다.
- [ ] 통합 검사의 취향 경고 `hue-count`·`tinted-surface`·`emoji-icon`·`numbered-markers`가 없다. 남겼다면 이유를 예외 주석으로 적었다.

## 화면 유형별

화면 유형의 뼈대·값은 `patterns/layout-principles/references/screen-conventions.md`에 있다. 요청에 없는 요소를 더하라는 항목은 없다 — 요청한 요소를 관례대로 두었는지 본다.

### 시세·증권

- [ ] 시세 화면이면 등락에 부호·▲▼가 붙고 `--color-rise`·`--color-fall`을 썼다. 데스크톱 종목 상세의 주문 패널이 첫 화면 안에 있다.

### 게이미피케이션

- [ ] 게이미피케이션 화면이면 축하는 지금 화면 위 오버레이 한 번(버튼 하나)이고, 1~3위·얻은 배지는 보상 색 그림, 못 얻은 배지는 회색 + 자물쇠다. 홈의 받기 버튼은 늘 그 자리에 있고(받을 것이 없으면 비활성 + 남은 조건), 연속 출석일·걸음 수 같은 숫자가 화면끼리 맞는다. 낭독 영역에 매초 바뀌는 값이 없다.

### 시작 안내·은행 홈

- [ ] 시작 안내는 화면 가운데 옅은 원 안의 큰 장면 하나(강조색 한 벌로 그린 SVG — 목업·빈 카드·목록·키운 그림 아이콘이 아니다)이고 글·점·버튼의 정렬이 하나다. 은행·자산 홈은 대표 계좌가 강조색 면 카드 하나이고 그 안 버튼 둘(송금·내역)이 같은 크기의 짝이다.

### 채팅방

- [ ] 채팅방은 화면 높이 가득(flex 세로 + `100dvh`)이고 입력 줄이 맨 아래에 있다. 대화 칸은 `min-height: 0; overflow-y: auto; position: relative`다. grid 틀이면 `grid-template-columns: minmax(0, 1fr)`이 있다(검사 규칙 `grid-blowout`·`hidden-text-escape`).

### 아이콘 자리·알림

- [ ] 큰 콘텐츠 칸(분류 바로가기·배너·가게 사진 대역)은 그림 아이콘이고, 목록 행(계좌·거래·알림)과 틀(탭 바·머리·버튼)은 선 아이콘이다. 거래·알림 행의 선 아이콘은 분류마다 모양이 다르고, 상품을 가리키는 알림은 상품 사진이다. 알림 행마다 본문 한 줄이 있고, 안 읽은 알림은 맨 위 2~3개, 탭 점은 안 읽은 탭에만 있다.

### 배달·숙소

- [ ] 배달 홈의 가게 카드는 사진 칸(높이 120~150, `art--dish` + 메뉴 그림, 3장 묶음 가능)이 크고, 숙소 상세의 객실 선택은 썸네일이 있는 행이다.

### 앱 화면·하단 탭 바

- [ ] 화면 유형의 뼈대를 따랐다 — 상세·폼·시작 안내의 주 행동은 하단 고정 바에 있다.
- [ ] 가로로 넘기는 줄(칩·날짜·상품)의 첫 항목이 본문 왼쪽 정렬선에 맞고, 화면 끝에서 잘리는 것은 오른쪽 끝뿐이다.
- [ ] 앱 화면이면 하단 탭 바는 탭의 첫 화면에만 있고, 하단 고정 바와 겹쳐 쌓이지 않는다. 키보드가 올라오면 숨는다.

### 모바일 웹뷰

- [ ] 모바일 웹뷰면 `viewport-fit=cover`·안전 영역·`100dvh`·입력칸 16px을 지켰고, 화면마다 주소가 있어 기기의 뒤로 가기가 동작한다.

### 글쓰기

- [ ] 상단 바에 닫기나 뒤로가 있다.
- [ ] 필수 표시가 라벨 옆이나 버튼 위처럼 늘 보이는 자리에 있다(안내 문구 안에만 있지 않다).
- [ ] 항목이 제목·본문·사진·분류 밖으로 더 있으면 작성 폼이다 — 칸마다 굵은 라벨, 글을 쓰는 칸은 같은 모양, 설명 칸은 5~6줄에서 시작.
- [ ] (데스크톱 작성 폼) 입력 열 안의 입력칸·세그먼트·칩 줄이 같은 폭이고, 항목이 6개를 넘으면 제목 붙은 구역으로 나눴다. 이미지·공개 설정·등록 요약은 오른쪽 패널로 둘 수 있다. 입력 열과 패널은 24~32 간격의 한 묶음이고, 사이트 머리·페이지 제목과 좌우 끝·왼쪽 정렬선이 맞는다(패널이 화면 끝으로 밀려 가운데가 비지 않았다). 회색 바탕 위 흰 패널 안의 입력칸은 1px 테두리 상자다.
- [ ] 고르는 칸은 값의 종류에 맞는 조작이다 — 2~3개는 세그먼트(한 칸이 늘 골라져 있다. 기본값이 없는 필수 선택은 테두리 칩이나 라디오), 4~8개는 칩(감싸기), 작은 수는 기본값이 든 스테퍼, 긴 목록·날짜는 행 → 시트. 기기 기본 날짜 칸을 그대로 두지 않았다.
- [ ] 금액이 있는 예약·신청 폼은 금액을 항목별 내역(항목 · 금액, 데이터에 있으면 추가 요금, 합계)으로 보이고, 하단 고정 바에 예상 금액과 주 버튼을 함께 뒀다. 요청에 없는 가게 정보·소요 시간 같은 구역·데이터는 더하지 않고 제안으로 적었다.
- [ ] (제목·본문뿐인 글쓰기) 제목·본문이 테두리·채움 없는 큰 입력이고(제목 18~20 굵게, 본문 16), 안내 문구가 곧 라벨이라 `aria-label`이 있다. 본문 칸에 크기 조절 손잡이가 없다(`resize: none`).
- [ ] 글자 수가 보이고, 사진은 작은 정사각 칸 줄 + "0/10" 같은 개수다. 큰 끌어놓기 업로드 영역과 서식 툴바가 없다.
- [ ] 필수 칸을 채우기 전에는 등록 버튼이 같은 자리의 비활성이고, 등록 뒤에는 쓴 글로 이동하거나 하단 시트로 알린다(토스트 한 줄로 끝내지 않는다).

### 필터·정렬

- [ ] 요청에 적힌 조건마다 목록 위 칩이 있고, 필터를 버튼 하나나 작은 글자 링크에 숨기지 않았다.
- [ ] 칩을 누르면 그 조건만 든 하단 시트가 열리고, 적용하면 칩 글자가 고른 값으로 바뀌며 "상품 N개" 같은 결과 수가 바뀐다. 결과가 0개인 조합에서도 조건과 초기화가 남는다.
- [ ] 상품 그림이 상품 이름과 맞고(먹는 상품이 가방·병 그림이 아니다), 태그가 줄을 바꿔 카드 높이가 들쭉날쭉하지 않다.

### 대시보드·리포트

- [ ] 지표 3~4개가 따로 떨어진 카드 줄이 아니라 한 패널 안의 묶음(탭이면 고른 지표의 큰 그래프로 바뀐다)이다.
- [ ] 기간이 프리셋 + 직접 선택(+ 비교)이고, 표 숫자는 오른쪽 정렬 + `tabular-nums`다. 320px에서 표·그래프가 화면 밖으로 넘치지 않는다(표는 값을 빼지 않고, 390px 첫 화면에 이름과 핵심 값이 함께 보인다). 1280px에서도 가장 긴 지표 값(금액)이 칸 안에 있다.
- [ ] 견본 숫자가 데이터 한 곳에 모였고, 지표·차트·표의 숫자가 서로 맞는다(같은 데이터에서 계산했다). 강조색을 "분석 도구라 파랑" 같은 업종 일반론으로 고르지 않았다.

### 기사·리뷰

- [ ] 사이트 머리(로고 + 주 메뉴 — 프로젝트에 메뉴가 없으면 흔한 구역 이름 3~5개)가 있고 좁은 화면에서 메뉴가 글자 중간에서 잘리지 않는다. 지어낸 메뉴 이름은 보고에 바꿀 값으로 적었다.
- [ ] 제목 묶음(분류 → 제목 → 부제 → 글쓴이 줄)의 기준선(왼쪽이나 가운데)이 하나이고, 본문 열은 640~720px·본문 17~19다. 소제목·인용이 본문과 확실히 다르다.
- [ ] 리뷰의 평점은 숫자 + 그림 하나다. 공유·구독 버튼은 요청에 없으면 더하지 않고 제안했다.

### 설정

- [ ] 디자인 기준이 없으면 폭 가득 목록이고, 켜진 스위치는 강조색·꺼진 트랙은 옅은 회색이며(예시 상태는 켜짐·꺼짐을 섞었다), 테마·언어는 현재 값 + 꺾쇠 행이고 누르면 바텀시트에서 바로 고른다. 넓은 화면에서는 흰 열을 위아래로 띄운 둥근 패널로 둔다.
- [ ] 요청한 행이 모두 있고, 요청에 없는 행(고객센터·약관·버전 등)은 더하지 않았다. 더할 만하면 보고에 제안했다.
- [ ] 프로젝트의 설정 화면이 이미 다른 모양(둥근 묶음·세그먼트 테마)이면 그 모양을 유지했다.

### 랜딩

- [ ] 요청한 구역이 모두 있고, 요청에 없는 구역은 마지막 행동 띠(주 행동을 한 번 더)말고는 더하지 않았다.
- [ ] 실제 서비스면 고객사 로고·사용자 수·후기·성과 수치가 사용자가 준 자료뿐이다. 자료가 없어 뺀 구역과 필요한 자료를 보고에 적었다.
- [ ] 명시적 가상 목업이면 지어낸 로고·수치·후기 구역마다 "예시" 표시가 화면에 보인다. 실존 회사 이름·로고가 없다.
- [ ] 히어로 제품 화면이 실제처럼 빽빽하고(첫 화면 안), 기능 구역마다 시각물이 있고 01·02·03 번호 목록이 아니다.
- [ ] 제품 화면 그림마다 `role="img"` + 한 문장 설명이 있고, 그 안에 진짜 버튼·링크가 없다. 그림이 좌우로 넘치지 않고, 390px에서는 한 열짜리 그림으로 바뀐다.
