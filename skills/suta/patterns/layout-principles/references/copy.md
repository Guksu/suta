# 문구 — UI 글쓰기 기준

화면을 잘 짜도 문구가 AI 티를 낸다. 한 화면 안에서 "담겼습니다"와 "담았어요"가 섞이고, "(데모)"·"테스트 계정: …" 같은 개발용 문구가 화면에 남고, 같은 행동을 버튼마다 다르게 부른다. 이 문서는 잘 만든 앱이 실제로 쓰는 문구를 역할별로 받아 적어 센 기준이다.

근거는 다음과 같다.

- 국내 앱 31곳의 화면 1,116장에서 서비스가 쓴 UI 문구 7,539개(홍보 문구 387개는 따로)를 역할별로 받아 적었다 — 제목·설명·버튼·대화상자·오류·빈 상태·토스트·입력 안내.
- 같은 지표로 AI 산출물 48개(일반 Claude 22개, suta를 설치한 Claude 26개)의 문구를 쟀다.
- 디자인 피드백 사례 중 문구를 다룬 것(문구는 칸의 대상 말로, 없어도 이해되는 설명은 뺀다, 칸에 들어갈 글자 수를 먼저 잰다).

레퍼런스도 늘 맞지는 않았다. 말투 섞임·같은 대상 다른 이름은 잘 만든 앱에서도 흔했다. 아래 기준은 다수가 하는 것과, 그들이 자주 틀리는 곳을 함께 적는다.

## 1. 한눈에

| 잰 것 | 잘 만든 앱 | 일반 Claude |
|---|---|---|
| 버튼 문구 길이 | 중앙값 4자, 6자 이하 76% | 중앙값 3자 |
| 버튼 꼴 | 명사 58%·`~기`(시작하기·담기) 36%, 문장형 5% | 명사 78%·`~기` 16% |
| 오류 문구 말투(서술문 중) | 해요체 87% | 표본 1개(해요체) |
| 토스트 말투 | 해요체 76% | 합쇼체(담겼습니다) |
| 한 화면 안에서 해요체·합쇼체가 섞인 화면 | 42%(서술문 2개 이상인 화면 358장 중 151장) | 7장 중 4장 |
| 개발·데모 문구가 화면에 남은 경우 | 문구 7,539개 중 2개 | 22번 중 11번 |
| 느낌표·이모지가 든 UI 문구 | 2.2%·0.9%(홍보 문구는 20.7%·3.4%) | 0.4%·0.8% |

## 2. 말투 — 해요체 하나

- **앱의 말투는 해요체 하나다.** 잘 만든 앱의 제목은 76%, 오류는 87%, 토스트는 76%가 해요체였다. 버튼·입력 안내·탭은 명사로 끝난다(94%).
- **합쇼체는 약관·개인정보 고지·법적 안내에만.** 레퍼런스의 설명 문장에서 합쇼체가 56%로 많았던 것은 대부분 이 고지 문장이다.
- **한 화면·한 앱 안에서 섞지 않는다.** 잘 만든 앱도 화면의 42%에서 "인증되었습니다"(토스트)와 "입력해 주세요"(제목)를 섞었다. 이것은 따라 할 관례가 아니라 그들이 자주 틀리는 곳이다. 검사 규칙 `mixed-tone`이 짧은 UI 문구의 섞임을 잡는다.
- 바꾸는 예: "삭제되었습니다" → "삭제했어요", "장바구니에 담겼습니다" → "장바구니에 담았어요", "올바르지 않습니다" → "다시 확인해 주세요", "\~하시겠습니까?" → "\~할까요?"
- **띄어쓰기는 한 꼴로.** "해 주세요"와 "해주세요"를 함께 쓴 서비스가 27곳 중 12곳이었다. 하나를 정해 모든 화면에 쓴다(표준은 띄어 쓰는 "해 주세요", 붙여 쓰기도 허용).
- 주어는 쓰지 않는다. "당신"·"고객님"·"회원님"을 문장마다 붙이지 않는다. 필요하면 이름을 부른다("서연 님, 생일이 언제인가요?").

## 3. 버튼

- **짧게, 행동의 이름으로.** 2~6자. 가장 많이 쓰인 채운 버튼은 다음(109번)·시작하기(38)·앱 다운로드(36)·확인(23)·로그인(18)이었다.
- **명사나 `~기`로 끝낸다.** "저장", "담기", "주문하기". 문장형("다 했어요!", "네, 좋아요")은 대화상자의 대답 버튼과 시작 안내에만(5%).
- **마침표·느낌표를 붙이지 않는다**(0.6%·0.7%).
- **같은 행동은 앱 전체에서 같은 이름.** 레퍼런스에서도 "시작하기"와 "계속하기", "휴대폰 번호"와 "휴대전화 번호", "암호"와 "비밀번호"가 한 앱 안에서 갈렸다. 용어 표를 하나 두고 맞춘다.
- 금액·개수를 버튼에 넣어도 된다("12,000원 주문하기"). 무엇을 누르는지가 더 분명해진다.
- 비활성 버튼은 글자를 바꾸지 않고 색으로 끈다. 막힌 이유는 버튼 위·입력칸 아래 한 줄로 알린다.

## 4. 대화상자

- **알림은 버튼 하나, "확인".** 잘 만든 앱의 대화상자 버튼 108벌 중 50벌이 "확인" 하나였다.
- **묻는 대화상자는 "취소" + 행동 이름.** "취소 / 확인"보다 "취소 / 삭제", "아니요 / 네, 받을게요"처럼 무엇이 일어나는지 쓴다. 되돌릴 수 없는 행동은 오류 빨강 글자로.
- **제목은 질문 한 문장.** "주문을 취소할까요?" 본문은 결과 한 줄("조리가 시작되면 취소할 수 없어요"). 제목만으로 충분하면 본문을 뺀다.

## 5. 오류·빈 상태·토스트

| 역할 | 잘 만든 앱 | 꼴 |
|---|---|---|
| 오류 | 중앙값 12자, 해요체 87%, 입력칸 바로 아래 빨간 한 줄 | 무엇을 + 어떻게: "사업자 번호를 정확하게 입력해 주세요", "두 글자 이상 적어 주세요" |
| 빈 상태 | 중앙값 13자, 27장 중 11장이 행동 버튼 하나 | 상황 한 줄 + 할 일 한 줄 + 행동 하나: "팔로우 중인 채널이 없어요 / 함께할 스트리머를 찾아보세요 / 추천 보기" |
| 토스트 | 중앙값 15자, 마침표 86%, 해요체 76% | 일어난 일을 과거형 한 문장: "장바구니에 담았어요." |

- **오류는 탓하지 않고 고칠 방법을 말한다.** "잘못된 형식입니다"보다 "이메일 주소를 확인해 주세요". 서버 오류 코드나 영어 원문("(500) Invalid parameter")을 그대로 보이지 않는다 — 레퍼런스에도 한 곳 있었다.
- **빈 상태에서 끝내지 않는다.** 다음 행동 하나(버튼이나 글자 버튼)를 둔다. 검색 결과 없음은 조건을 유지한 채 "조건 지우기"를.
- **토스트에는 버튼을 달지 않는다**(`toast-stack` 패턴). 고칠 자리가 있는 문제는 토스트가 아니라 그 자리의 오류 줄로.
- 마침표는 문장이면 찍고, 명사구면 찍지 않는다. 한 앱 안에서 같은 역할은 같게.

## 6. 제목·보조 줄·입력 안내

- **화면 제목은 짧게**(중앙값 8자, 마침표 15%). 입력 화면은 묻는 문장 하나("통신사가 어디인가요?")가 흔하다. 질문형 제목은 6%였다.
- **보조 줄은 제목을 되풀이하지 않는다.** 이유·조건·숫자를 담는다: "입력한 이메일은 인증에만 사용돼요", "언제든 설정에서 바꿀 수 있어요", "한글 1자, 영문 2자 이상". 없어도 이해되는 설명은 뺀다.
- **입력 안내(placeholder)는 명사로**(91%, 중앙값 6자): "이름 입력", "생년월일 6자리". 라벨을 대신하지 않는다 — 라벨은 칸 위에 남긴다(`floating-label`).
- 칸에 들어갈 글자 수를 먼저 잰다. 버튼·탭·카드 제목은 10자 안팎에서 줄이 바뀐다. 가장 긴 문구로 확인한다.

## 7. 쓰지 않는 것

| AI가 흔히 하는 것 | 대신 |
|---|---|
| "(데모)", "테스트 계정: demo@example.com / 1234", "가상의 예시 데이터", "샘플 상품 담기", "Lorem ipsum"을 화면에 둔다 | 사용자가 볼 문구만. 지어낸 값이라는 안내는 코드 주석·README에 (`meta-copy` 규칙) |
| 오류 상태를 보이려고 "형식 오류·빈 입력·인증 실패" 같은 미리보기 버튼을 화면에 둔다 | 실제 입력으로 상태가 바뀌게 한다. 상태 확인은 개발 도구에서 |
| 같은 문단에서 "\~해요"와 "\~합니다"를 섞는다 | 해요체 하나(약관만 합쇼체) |
| 버튼·제목에 느낌표·이모지 | UI 문구에는 쓰지 않는다. 홍보 배너에서만(레퍼런스 홍보 문구의 느낌표 20.7%) |
| 홍보 문구를 "스마트한·똑똑한·합리적인" 같은 평가어로 채운다 | 숫자와 사실로: "3초 만에 시작", "재이용률 85%". 레퍼런스 홍보 문구의 29%에 숫자가 있었다 |
| 영어와 한국어를 섞는다("My 쿠폰", "BEST 메뉴") | 한 언어로. 영어 탭·영어 라벨을 쓰면 앱 전체를 영어로 |

## 8. 마무리 점검

- [ ] 앱의 말투가 해요체 하나다. 합쇼체는 약관·법적 고지에만 있다. "해 주세요" 띄어쓰기가 한 꼴이다.
- [ ] 버튼은 2~6자의 명사나 `~기`이고, 마침표·느낌표가 없다. 같은 행동은 같은 이름이다.
- [ ] 묻는 대화상자의 버튼이 "취소" + 행동 이름이다. 알림은 "확인" 하나다.
- [ ] 오류는 무엇을 어떻게 고칠지 말하고, 그 칸 바로 아래에 있다. 오류 코드·영어 원문이 보이지 않는다.
- [ ] 빈 상태에 다음 행동이 하나 있다.
- [ ] 화면에 개발·데모 문구가 없다.
- [ ] 같은 대상을 한 이름으로 부른다.
