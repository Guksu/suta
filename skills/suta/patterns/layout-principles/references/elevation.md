# 층 — 화면의 앞뒤

화면에는 앞뒤가 있다. 내용이 놓인 면이 있고, 그 위에 붙어 있는 머리와 탭 바가 있고, 잠깐 떠오르는 메뉴와 토스트가 있고, 뒤 화면을 덮는 시트와 모달이 있다. 이 차이가 보여야 무엇이 지금 눌리는지, 무엇이 닫히는지 알 수 있다.

AI는 두 방향으로 틀린다.

- 모든 카드에 그림자를 준다. 모든 것이 같은 높이로 떠 있으면 높이가 없는 것과 같다.
- 반대로 상자를 걷어 내면서 메뉴·시트까지 평평하게 둔다. 떠 있는 것이 놓인 것과 같은 면에 있어 어디가 위인지 알 수 없다.

값도 그때그때 고른다. 그림자는 요소마다 다르고, `z-index`는 9999가 된다.

**쓰는 범위.** 프로젝트에 그림자·겹치는 순서의 체계가 있으면 그것을 쓴다. 아래에서 사용 문제는 두 가지다. 겹치는 순서가 틀려 조작이 가려지는 것(탭 바가 시트를 덮는다, 고정 머리가 메뉴를 덮는다)과, 덮는 것 뒤의 화면이 그대로 눌리는 것이다. 이 둘은 기존 체계에서도 고친다. 그림자 값과 단계 수는 취향이다.

**근거.**

- 국내 앱 화면 기록(31곳 1,116장): 카드의 71%가 테두리·그림자 없이 톤 차이로 나뉜다. 테두리와 그림자를 함께 쓴 카드는 1%다.
- 공개 웹사이트 실측(2026-11): 국내 서비스와 해외 제품 사이트 60곳 중 47곳의 첫 화면부터 세 화면 높이까지를 데스크톱 1440(38곳)과 모바일 390(45곳)에서 계산된 스타일로 쟀다. 열리지 않은 7곳과 robots.txt가 막은 6곳은 뺐다. 값은 아래 절마다 적었다. 메뉴·모달은 열어 보지 않았다. 그 그림자 값은 실측이 아니라 이 스킬의 패턴 코드가 써 온 값을 세 단계로 모은 것이다.

## 1. 네 층

| 층 | 무엇 | 뒤와 나누는 법 | 그림자 | 겹치는 순서 |
|---|---|---|---|---|
| 놓인 것 | 바탕, 면, 카드, 목록 행, 입력칸 | 톤 차이(옅은 바탕 위 흰 면), 간격, 얇은 선 | 없음 | 없음 |
| 붙은 것 | 고정 머리, 탭 줄, 하단 탭 바, 하단 고정 바 | 불투명한 면. 더한다면 1px 선 | 없음. 쓰는 체계라면 스크롤됐을 때만 옅게 | `--z-sticky` |
| 뜬 것 | 메뉴, 자동완성, 툴팁, 토스트, 떠 있는 버튼, 끌고 있는 항목 | 그림자 | `--shadow-raised` | `--z-popover`, 토스트는 `--z-toast` |
| 덮는 것 | 시트, 모달, 사이드 패널, 전체 화면 뷰어 | 스크림(뒤를 어둡게 하는 막) + 뒤 화면 잠금 | 모달은 `--shadow-overlay`. 시트는 스크림만으로 된다 | `--z-overlay`, 뷰어는 `--z-viewer` |

어느 층인지는 두 가지를 물어 정한다.

1. 닫히거나 사라지는 것인가. 아니면 놓인 것이나 붙은 것이다. 그림자를 쓰지 않는다.
2. 열려 있는 동안 뒤 화면을 쓸 수 있는가. 쓸 수 있으면 뜬 것이다(그림자, 스크림 없음). 쓸 수 없으면 덮는 것이다(스크림, 뒤 화면 `inert`).

카드는 닫히지 않는다. 그래서 놓인 것이고 그림자가 없다. 메뉴는 닫힌다. 그래서 테두리만 두면 안 되고 떠 보여야 한다.

## 2. 그림자 — 세 단계

토큰은 `assets/layout-tokens.css`에 있다. 이 문서의 `assets/` 경로는 `patterns/layout-principles/` 기준이다. 이 스킬의 패턴 CSS는 `var(--shadow-raised, 값)`처럼 토큰을 먼저 찾고, 없으면 같은 값을 쓴다. 토큰 파일을 넣지 않아도 모양은 같고, 넣으면 한 곳에서 바꿀 수 있다. 겹치는 순서(`--z-*`)도 같은 방식이다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--shadow-low` | `0 1px 3px rgb(0 0 0 / 0.2)` | 트랙 위를 미끄러지는 손잡이(스위치·슬라이더) |
| `--shadow-raised` | `0 1px 2px rgb(0 0 0 / 0.08), 0 8px 24px rgb(0 0 0 / 0.12)` | 메뉴·자동완성·툴팁·토스트·떠 있는 버튼 |
| `--shadow-overlay` | `0 2px 6px rgb(0 0 0 / 0.1), 0 24px 64px rgb(0 0 0 / 0.24)` | 모달, 끌어 올린 항목 |

- **놓인 카드에는 그림자를 쓰지 않는다.** 옅은 바탕 위 흰 면의 톤 차이로 나눈다. 실측한 사이트에서 놓인 카드에 그림자가 하나라도 있는 곳은 데스크톱 38곳 중 15곳, 모바일 45곳 중 13곳이었다. 그림자 카드를 쓰는 디자인 체계라면 한 단계만 쓰고, 테두리와 함께 쓰지 않는다.
- **무채색이다.** 색이 든 번지는 그림자(버튼 아래의 파란 빛)는 높이가 아니라 빛나는 효과로 읽힌다. 실측에서 그런 그림자가 있는 곳은 38곳 중 2곳, 45곳 중 2곳이었다. 검사 규칙 `glow-shadow`가 잡는다.
- **방향은 아래 하나다.** 가로 이동(x)은 0이다. 방향이 섞이면 빛이 여러 곳에 있는 것처럼 보인다. 옆에서 들어오는 패널만 들어온 쪽의 반대로 떨어진다.
- **두 겹으로 쓴다.** 바로 아래의 짧고 진한 층이 닿은 자리를, 넓고 옅은 층이 높이를 보인다. 한 겹의 큰 그림자는 뿌옇게 번지기만 한다.
- **세 단계를 넘기지 않는다.** 값이 요소마다 다르면 높이가 그만큼 여러 단계로 보인다. 실측에서 한 사이트가 쓴 바깥 그림자 값은 중앙값 1종이었고, 4종 이상은 38곳 중 4곳, 45곳 중 2곳이었다. 떠 있는 요소의 그림자는 흐림 6/8/24px, 불투명도 0.06/0.12/0.2였다(아래 사분위·중앙값·위 사분위, 데스크톱). 검사 규칙 `shadow-variety`가 한 파일의 4종 이상을 잡는다.
- **호버에 그림자를 키우지 않는다.** 놓인 것이 떠오르는 경우는 끌어 올릴 때뿐이다. 호버는 면의 톤으로, 눌림은 살짝 줄어드는 것으로 보인다(`patterns/press-feedback`).
- **`box-shadow` 값을 움직이지 않는다.** 프레임마다 다시 칠한다. 그림자를 `::after`에 두고 `opacity`를 움직인다.
- **어두운 바탕에서는 그림자가 보이지 않는다.** 뜬 면을 뒤보다 한 단계 밝게 하고, 1px 밝은 선(`rgb(255 255 255 / 0.1)`)을 두른다.

## 3. 붙은 것 — 불투명한 면, 더한다면 선 하나

- 고정 머리는 불투명한 면이면 된다. 내용이 그 밑으로 들어가 가려지는 것으로 붙어 있음이 보인다. 실측에서 스크롤한 뒤에도 고정 머리에 선도 그림자도 없는 곳이 가장 많았다(데스크톱 23곳 중 13곳, 모바일 28곳 중 18곳).
- 나눔이 필요하면 1px 선(`--color-line`) 하나를 둔다(23곳 중 5곳, 28곳 중 5곳). 옅은 그림자를 쓰는 곳도 같은 수였다(5곳, 5곳). 둘을 함께 쓰지 않는다.
- 선이나 그림자는 맨 위에서는 없다가 스크롤돼 내용이 밑으로 들어왔을 때 생긴다. 맨 위에서는 머리와 내용이 한 면이다(맨 위에서 고정 머리가 있던 21곳 중 16곳이 아무것도 없었다). `patterns/sticky-header`는 접혔을 때만 아래 그림자가 `opacity`로 나타난다.
- 하단 탭 바와 하단 고정 바는 위쪽에 1px 선을 둔다. 위로 번지는 그림자는 쓰지 않는다.
- 반투명 유리는 화면에 한 곳만 쓴다(`patterns/glass-nav`). 유리 머리는 23곳 중 1곳, 28곳 중 4곳이었다.
- 붙은 것을 쌓지 않는다. 위에 머리 한 줄, 아래에 한 줄이다.
- 붙은 것은 내용을 가린다. 본문 아래에 바 높이 + `env(safe-area-inset-bottom)`만큼 여백을 두고, 닻(앵커)으로 가는 제목에는 `scroll-margin-top`을 머리 높이만큼 둔다.

## 4. 덮는 것 — 스크림과 잠금

- 스크림은 `--scrim`(`rgb(0 0 0 / 0.5)`)이다. 뒤 화면이 지금 눌리지 않는다는 표시다. `opacity`만 움직인다.
- 뒤 화면은 `inert`로 잠그고 스크롤을 멈춘다. 스크림을 누르거나 Esc를 누르면 닫히고, 포커스가 연 자리로 돌아간다(진입 스킬 `SKILL.md`의 "접근성").
- 시트는 위 모서리만 둥글다(`--radius-sheet`). 뒤 화면이 위로 조금 보이는 높이까지만 올라온다(`patterns/bottom-sheet`의 기본 최대 높이는 화면의 85%다). 뒤 화면이 보여야 덮은 것으로 읽힌다. 화면을 다 채워야 하면 시트가 아니라 화면 전환이다.
- 덮는 것은 한 번에 하나다. 시트 위에는 묻는 대화상자 하나까지만 연다. 스크림을 두 겹으로 겹쳐 더 어둡게 하지 않는다.
- 사진 위 글자를 받치는 그라데이션 막은 다른 것이다. 그 막은 글자가 읽히는 만큼만 깐다(`references/principles.md` P9).

## 5. 겹치는 순서

숫자를 그때그때 고르지 않는다. 큰 숫자 자체가 결함은 아니다. 실측한 사이트도 1000 이상을 흔히 썼다(데스크톱 35곳 중 15곳). 결함은 단계가 없는 것이다. 요소마다 숫자를 새로 고르면 무엇이 무엇 위에 오는지 아무도 모르게 되고, 9999 다음은 99999가 된다.

| 토큰 | 값 | 무엇 |
|---|---|---|
| `--z-sticky` | 30 | 고정 머리, 탭 줄, 하단 탭 바, 하단 고정 바 |
| `--z-overlay` | 40 | 스크림(40)과 그 위의 시트·사이드 패널(41) |
| `--z-popover` | 50 | 메뉴, 자동완성, 툴팁. 시트 안에서도 열리므로 덮는 것보다 위다 |
| `--z-viewer` | 90 | 전체 화면 뷰어(사진 확대·스토리) |
| `--z-toast` | 100 | 토스트. 무엇이 열려 있어도 보인다 |

단계 안에서는 +1·+2로 쌓는다. 컴포넌트 안의 작은 순서(글자가 표시 위, 1·2)는 그 컴포넌트에 `isolation: isolate`를 두어 밖으로 새지 않게 한다.

| 흔한 결함 | 원인 | 고치는 법 |
|---|---|---|
| 하단 탭 바가 시트와 스크림 위에 그려진다 | 탭 바의 순서가 시트보다 높다 | 붙은 것은 `--z-sticky`, 시트는 `--z-overlay` |
| 고정 머리가 열린 메뉴를 덮는다 | 메뉴의 순서가 머리보다 낮거나 같다 | 메뉴는 `--z-popover` |
| `z-index`를 올려도 위로 오지 않는다 | 조상이 새 쌓임 맥락이다. `transform`·`filter`·`opacity` 1 미만·`will-change`·`contain`이 있는 조상 안의 `z-index`는 그 안에서만 통한다 | 떠야 하는 것을 `body` 가까이에 그린다. 또는 네이티브 `dialog`·`popover`를 쓴다 |
| 메뉴가 카드 끝에서 잘린다 | 조상에 `overflow: hidden`이 있다 | 메뉴를 `position: fixed`로 두고 여는 버튼의 자리를 재서 놓는다(`patterns/dropdown-menu`) |
| 토스트가 모달 밑에 깔린다 | `dialog.showModal()`은 브라우저의 맨 위 층이다. 어떤 `z-index`보다 위다 | 모달이 열려 있는 동안의 알림은 모달 안에 둔다 |

## 6. 그림자 없이 앞뒤를 낸다

그림자를 줄여도 화면이 평평해지지 않는다. 앞뒤는 톤과 겹침과 움직임에서 나온다.

| 수단 | 어떻게 | 패턴 |
|---|---|---|
| 톤 | 옅은 바탕(`--color-canvas`) 위 흰 면(`--color-surface`). 한 단계만 쓴다. 회색 위에 회색을 겹치지 않는다 | — |
| 겹침 | 사진 위에 머리의 뒤로 버튼이 겹친다. 시트가 올라와도 뒤 화면이 위로 보인다. 가로 줄의 다음 카드가 화면 끝에서 잘려 보인다 | `bottom-sheet`, `carousel`, `card-stack` |
| 스크롤 | 내용이 머리 밑으로 들어가고, 당기면 대표 사진이 늘어난다 | `sticky-header`, `stretchy-header` |
| 전환 | 새 화면이 옆에서 들어오며 앞 화면이 조금 물러난다. 카드가 그 자리에서 커져 상세가 된다 | `page-transition`, `card-expand` |
| 크기 | 가까운 것은 크고 진하다. 1순위 하나가 본문의 1.5배 이상이다 | — |

## 7. AI가 흔히 하는 것

| AI가 흔히 하는 것 | 대신 |
|---|---|
| 모든 카드에 그림자, 호버하면 그림자가 커지며 위로 2px 떠오른다 | 카드는 그림자 없이 톤 차이로. 호버는 면의 톤 한 단계 |
| 버튼·카드 아래에 강조색이 번지는 그림자 | 무채색 그림자를 떠 있는 것에만. 강조는 채운 면 하나 |
| 카드에 테두리와 그림자를 함께 | 톤 차이. 꼭 쓰면 둘 중 하나 |
| 고정 머리에 늘 그림자, 하단 바에 위로 번지는 그림자 | 불투명한 면. 더한다면 스크롤됐을 때 1px 선 하나 |
| 메뉴·자동완성을 테두리만 두른 평평한 상자로 | `--shadow-raised`. 닫히는 것은 떠 보인다 |
| 시트·모달 뒤에 스크림이 없거나, 스크림 뒤의 화면이 눌린다 | `--scrim` + 뒤 화면 `inert` |
| 요소마다 새로 고른 `z-index`(9999, 99999) | 단계 토큰 다섯 개 |
| 어두운 화면에 밝은 화면과 같은 검은 그림자 | 뜬 면을 한 단계 밝게 + 1px 밝은 선 |
| 그림자 값이 요소마다 다르다 | 세 단계 |

## 8. 확인

- [ ] 놓인 것(카드·목록·입력칸)에 그림자가 없다. 그림자는 닫히거나 사라지는 것에만 있다.
- [ ] 그림자가 무채색이고 아래 방향이며 세 단계 안이다.
- [ ] 메뉴·자동완성·툴팁·토스트가 뒤의 면과 그림자로 구별된다.
- [ ] 시트·모달 뒤에 스크림이 있고 뒤 화면이 눌리지 않는다.
- [ ] 시트를 열면 하단 탭 바와 고정 머리가 스크림 밑에 있다. 메뉴는 고정 머리 위에 열린다.
- [ ] `z-index`가 단계 토큰이거나 컴포넌트 안의 1·2다.
- [ ] 고정 머리는 불투명하고, 선이나 그림자는 스크롤됐을 때만 하나 있다. 붙은 것이 위아래에 한 줄씩이다.
- [ ] 통합 검사의 `glow-shadow`·`shadow-variety`가 없다. 기존 체계의 값이면 그대로 두고 보고에 적는다.
